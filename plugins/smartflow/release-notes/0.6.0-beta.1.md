# SmartFlow 0.6.0-beta.1

Fifth wave-1 content build: the frontend QA Skills and the documentation layer.

## Added — Skills

- `frontend-section-qa` (rewritten from the legacy frontend-design-qa Skill for the single wp-content-level workspace): injection-proof is now the main mode — all visual iteration happens by injecting the planned rules into the served page through Playwright MCP, with the full viewport ladder, variants, and states verified injection-proofed and no per-tweak deploy rounds. The bridge-verified served check is a one-time confirmation: one bundled deploy pass (commit with trailer, hard stop, user pushes), `deployed_commit` verified over the status bridge with a bounded retry budget (max 3 re-checks) and a clean abort message on hash mismatch, then one served confirmation pass. The Skill consumes and writes back the Section work record in the project docs layer (Visual QA Targets matrix result cells, status fields, QA notes) — there is no handoff file — and closes by refreshing the Section doc through a scoped `auto-docs` run. Playwright MCP preflight with Capability Probe, Degraded Mode for partial tool defects, and the no-substitute-browser rule carry over from the prototype work.
- `cpt-frontend-qa` (rewritten on the same model): per-surface injection-proofed iteration (card, archive/grid, carousel/filter, WPGB output, optional single), per-surface injection-proof status fields, the same bundled deploy pass, bounded bridge verification, and one-time served check on the display URL and — when public detail pages exist — a representative single URL. Consumes and writes back the CPT work record; WPGB IDs come from the work record or the bridge, never guessed.
- `wp-media-import` (converted from WP-CLI to the WordPress REST API): duplicate check over `GET /wp/v2/media?search=`, filename normalization, upload over `POST /wp/v2/media` with explicit failure handling (401/403, 413, 5xx), metadata in one update request, cache flushes through the status bridge instead of WP-CLI, verification over `_fields` plus `source_url`, and attachment IDs recorded in the affected work record. There is no server shell in the SmartFlow workspace.
- `auto-docs` (ported from the Confluence skill intake, Tobias Uhl; adapted to SmartFlow): generates and maintains `docs/` at the repository root with canonical categories `sections`, `elements`, `post-types`, `field-groups`, `coding-standard`. Content generation always runs through worker subagents (one per element, parallel, main context stays small); the delta check runs over git timestamps, not mtime. ACF field-group docs are generated from the PHP field-group sources per the `acf-php-field-groups` standard, with the original `generate.js` retained as the legacy path for admin JSON exports (ported to `docs/field-groups/`, full frontmatter added). The Section template embeds the `Visual QA Targets` matrix and the QA notes as protected work-record sections, so the legacy handoff files dissolve into the generated docs structure: `docs/sections/<slug>.md` and `docs/post-types/<resource>.md` are simultaneously work record and permanent documentation, and auto-docs never regenerates filled matrix rows or QA state. New `field-group.md` and reconstructed `readme-index.md` templates ship alongside the ported `section.md`, `element.md`, and `coding-standard.md`.
- `cpt-docs` (ported from the Confluence skill intake, Tobias Uhl; adapted to SmartFlow): documents one CPT to `docs/post-types/<resource>.md` — the CPT work record — from read-only REST discovery plus `GET /wso/v1/status` on the bridge (ACF field groups with `local: php`, WPGB grid/card IDs) and repo discovery against the PHP field groups and WST card/single templates. The doc template carries the auto-docs frontmatter, the Visual QA Targets section per surface, and the work-record protection; the legacy handoff and `wp-rest-env` references are replaced by the work record, `PROJECT-CONTEXT.md`, and the `status-bridge` Rule. Also serves as the post-types worker template inside an auto-docs full run.

## Notes

- With this build the handoff dissolution from the rework plan is complete on the consuming side: `wst-section-workflow` and `wst-new-post-type` create the work records, the frontend QA Skills fill the QA matrix and deploy state, and the docs Skills preserve those sections while keeping the documentation around them current.
- `setup-playwright-mcp` is deliberately not ported as its own Skill; Playwright MCP setup and repair route to Step 8 of `setup-local-project`.
- Remaining wave-1 gap: the Commands layer. Wave 2 (`figma-page-builder`, `jira-ticket-workflow`, `jira-batch-workflow`) follows once the wave-1 routing targets are stable.
