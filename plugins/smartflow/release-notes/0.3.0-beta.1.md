# SmartFlow 0.3.0-beta.1

Second wave-1 content build: the migrated rules layer and the five package subagents.

## Added — Rules

- `webroot-safety`: shrunk from the legacy full-webroot rule to the deploy-path boundary. The wp-content-level repository root is never served; only the child theme deploy path needs webroot precautions, and `docs/`, `.cursor/`, `.env`, and `tmp/` are structurally safe.
- `deploy-and-branches` (new): the agent commits and hands over with a hard stop, never pushes; deploy-needing work is bundled into one pass; deploys are verified over the status bridge (`deployed_commit` vs local HEAD) before any served QA pass; branch changes only on explicit user instruction.
- `secrets` (new): the tracked repo-root `.env` pushed to the private remote is a deliberate, accepted decision that must not be "fixed"; secrets enter commands exclusively through environment variables and never appear as literals in tracked files, chat, logs, diagnostics, or docs.
- `acf-php-field-groups` (replaces the legacy `programmatic-acf-db-writes`): all ACF field definitions are PHP registrations under `smart-template-builder/acf/field-groups/`; the Flexible Content container and its layouts are registered in PHP together after a one-time per-project migration; structural ACF database writes are forbidden entirely — the clone-source data-loss class is structurally impossible because field groups are no longer database records.
- `file-edit-boundary` (adapted): boundary rewritten for the wp-content-level repository — editable child theme (incl. WST source and PHP ACF field groups), docs layer, and workspace config; off-limits WST plugin folder, third-party code, uploads, and any direct server edit; `functions.php` forbidden, `theme-functions.php` confirmation-only, bridge managed block only via the `install-status-bridge` Skill.
- `commit-trailer` (adapted): `Made with: SmartFlow` on every commit in the commit-and-hand-over flow; now maintained in the SmartFlow plugin.
- `css-guideline` and `figma-to-code` (rewritten verification): the two proof modes are now injection-proof and the bridge-verified served check (status bridge confirms `deployed_commit` matches the local commit before served results count); the legacy source-served wording and the handoff phase contract are gone — work records live in the project `docs/` layer.
- `wst-php-authoring-route` (from `Tests/`): child-theme PHP goes through the WST workflows and the `wst-shortcode-implementer` subagent; WST templates compose existing shortcodes.
- `frontend-section-qa-layout-preflight` (from `Tests/`): Figma layout model extraction, container fit check, and the Playwright px measurement matrix before and after the injection proof.
- `frontend-section-qa-tablet-band` (from `Tests/`): the full QA viewport ladder with deliberate 768-991px tablet-band styling before any final QA pass; rung values reconciled with `PROJECT-CONTEXT.md`.
- `playwright-browser-claim` (from `Tests/`): atomic claim/release protocol over `.cursor/pw-locks/` for parallel Playwright MCP servers; inert with a single server.
- `wordpress-brand-tokens` (from `Tests/`, genericized): brand tokens instead of hardcoded brand colors; per-brand palettes centralized via `.brand-<slug>` body-class blocks.
- `wordpress-taxonomies` (from `Tests/`, adapted): English `wso_tax_*` machine names, CPT UI managed registration prepared for the user, permalink flush through the status bridge.
- `wst-conditional-nesting` (from `Tests/`): never nest the same WST conditional tag name; named-level chain plus `wst_include` for shared partials; skipping suffix levels is treated as unverified runtime behavior.
- `agent-routing` (new, from the `Tests/agents` routing table): delegation and write-scope table for the five bundled subagents, pinned model routing with the pre-spawn availability check (missing models are reported, never silently substituted), and the shared fixed return contract.

## Added — Agents

The five package subagents from the CPT workflow prototype, rewritten for the single wp-content-level workspace (no server/local phase split; runtime facts over the status bridge; work records in the project `docs/` layer; subagents never commit, push, or flush):

- `cpt-codebase-analyst` (readonly, `composer-2.5-fast`)
- `cpt-figma-analyst` (`gpt-5.6-sol-medium`)
- `wst-shortcode-implementer` (`composer-2.5-fast`)
- `wpgb-specialist` (`claude-sonnet-5-thinking-medium`) — new bridge-based write scope: WPGB config is read over the bridge; config changes ship as an exact minimal apply-spec for the admin (or a project-validated write route) instead of direct database writes.
- `cpt-visual-implementer` (`composer-2.5-fast`)

## Removed Relative To The Legacy Packages

- `server-phase-boundary` and `wp-cli-cache` are not ported: there are no phases anymore, and the status bridge (0.2.0-beta.1) replaced the WP-CLI cache path.
- `programmatic-acf-db-writes` is superseded by `acf-php-field-groups`.

## Notes

- The runner agents delegate into `wst-new-post-type`, `wst-section-workflow`, `frontend-section-qa`, and `cpt-frontend-qa`; those Skills land in the remaining wave-1 migrations of the SmartFlow rework plan.
- Open runtime questions (ACF fully in PHP, WPGB writability without the admin, the conditional suffix chain) are tracked as open validations in the development repository.
