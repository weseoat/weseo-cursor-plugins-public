# SmartFlow 0.2.0-beta.1

First wave-1 content build on top of the 0.1.0 scaffold: the SmartFlow status bridge.

## Added

- `install-status-bridge` Skill with the bundled PHP template `reference/js-snippets-status-bridge.php` (bridge version 1.0.0). The template is a managed block for the child theme's `js-snippets.php` that registers the REST namespace `wso/v1`:
  - `GET /status`: `bridge_version`, `deployed_commit` (from `.wso-deployed-commit` in the child theme root, written by the project deploy path), registered ACF field groups (including PHP/JSON/DB origin), WP Grid Builder grids, and cache state (external object cache, detected page cache plugins, last flush timestamps).
  - `POST /flush-cache`: object cache plus best-effort purges for detected page cache plugins.
  - `POST /flush-permalinks`: soft rewrite-rules flush.
  - Every route requires an authenticated user with `manage_options` (WordPress application password through environment variables).
- `status-bridge` Rule: enforces the version comparison before every bridge use (`bridge_version` against the bundled template, `deployed_commit` against local HEAD for deploy verification), sets the bounded retry and abort budget (max 3 re-checks, then abort with a clear hand-over message instead of an endless loop), and replaces the legacy `wp-cli-cache` flush path with the bridge flush routes.

## Notes

- The agent never pushes: bridge install and update end in a commit plus hard stop; the user pushes, the deploy path delivers the child theme, and the agent verifies the deployed commit over `wso/v1/status` before QA continues.
- Project-specific values (site URL, credential environment variable names, deployed-commit write mechanism) are recorded in the project-local `PROJECT-CONTEXT.md`.
