# SmartFlow 0.4.0-beta.1

Third wave-1 content build: the setup and migration Skills for the local workspace model.

## Added — Skills

- `setup-local-project` (replaces the legacy Remote-SSH `setup-orientation`): guided German wizard for the first setup of the local SmartFlow workspace. Clones the wp-content-level repository, names the local folder exactly after the server hostname so Chrome DevTools Local Overrides and Cursor operate on the same files, has the user fill the tracked repo-root `.env` with the WordPress application password (names recorded, values never leave `.env`), runs the REST test (`/wp/v2/users/me` with `manage_options`), guides the `weseo-git-installer` configuration (repository, deploy branch, child theme target directory, Bitbucket push-to-deploy registration, deployed-commit contract, pending go-live deregistration), creates the read-only FTP user scoped to `wp-content` with a `.ftpaccess` limit that is verified in both directions (read works, write denied), installs the status bridge through the bundled `install-status-bridge` Skill as the first end-to-end deploy-chain test, configures Playwright MCP in the untracked `.cursor/mcp.json`, and fills `PROJECT-CONTEXT.md` including deploy branch and bridge version. Resumable from any starting state over recorded gate statuses.
- `migrate-ssh-to-local` (new): self-contained one-time migration of an existing project off the legacy Remote-SSH plus WP Pusher model; requires no legacy package. Export stage in the old SSH workspace: inventory (WP Pusher config, WPGB IDs, handoffs, ACF group list), read-only ACF export of the Page-Builder Flexible Content group and the shared TMPL clone-source groups to PHP field groups under `smart-template-builder/acf/field-groups/` with unchanged keys and a diff verification, then the backup-first deletion of the admin-created database groups (dump, live PHP-registration check, explicit user confirmation, trash instead of force-delete, re-verification), and a migration bundle outside the webroot. Import stage in the new local workspace: foundation via `setup-local-project`, theme and docs import with an FTP diff against the server, `PROJECT-CONTEXT.md` translation (SSH-era fields removed, SmartFlow fields added), WP Pusher unlink before the `weseo-git-installer` build-up so the two deploy paths never race, bridge-verified first deploy, WP Pusher uninstall only after verification, and an acceptance pass over `wso/v1/status` (`local: "php"` for all migrated groups) that closes the "ACF fully in PHP" open validation.

## Notes

- The ACF database-group deletion in `migrate-ssh-to-local` is the sanctioned one-time exception anticipated by the `acf-php-field-groups` Rule; after the migration, structural ACF database writes remain forbidden entirely.
- The WST and frontend workflow Skills and the Commands land in the remaining wave-1 and wave-2 migrations of the SmartFlow rework plan.
