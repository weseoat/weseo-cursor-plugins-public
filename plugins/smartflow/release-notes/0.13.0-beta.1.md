# SmartFlow 0.13.0-beta.1

The Project CSS Setup Skill: reconcile a project's global theme CSS values with its Figma design in one resumable pass, before Section work bakes the master install's values into workarounds. Decision log: `docs/project-css-setup-plan.md` (grill-me interview 2026-08-26); analysis lineage: the naturelhotels `text-images-two` misdiagnosis (`plugin-feedback/frontend-section-qa-layout-preflight.md`).

## Added

- `project-css-setup` Skill: four resumable blocks in fixed order — content widths, fonts, colors/brand tokens, buttons and global spacing — each running the same loop (extract from the design, compare with the theme, per-value confirmation, injection-proofed write, viewport-ladder verification). Entry reads the `css_setup` marker in `PROJECT-CONTEXT.md`: master-values mode (pending — set directly from the design) vs adapted mode (per-value theme-vs-design diff, the user decides per value). Before every value change an impact map is built (docs-layer work records plus `var()` consumer search); the affected-Sections list is shown in the confirmation, becomes the post-change Playwright spot-check plan, and doc gaps found via CSS search are written back. Value derivation: calculate once at the 1920 design anchor (design px / anchor rem basis), let the fluid rem basis do the scaling — no percentage re-derivation per breakpoint (that shrinks twice) — walk the full viewport ladder in the browser, verify 375 as the second design anchor, and set targeted per-breakpoint overrides only where a rung visually fails, with recorded reasons. Writes go through the standard SmartFlow chain (injection-proof, tracked theme CSS plus `PROJECT-CONTEXT.md` value blocks, one bundled commit with the SmartFlow trailer, hard stop, the user pushes); the marker flips to `reconciled (<date>)` when at minimum the widths block is done, per-block status keeps the fine-grained state. Runs in the main chat by design — the per-value confirmations are interactive.
- Bundled measurement reference `reference/viewport-measurement.md`: the standard Playwright `browser_evaluate` snippet that reads rem basis, container inner width, side margin, and optional per-block probes per ladder rung and returns them as one results-table row — every project measures the same way. Documents the 991px fractional-devicePixelRatio pitfall once: keep the 991 row, measure at 990 in Playwright MCP.

## Changed

- `setup-local-project`: new intro records the clone model (see Notes); the wizard now asks which master installation the project was cloned from, writes `Cloned from` and the `css_setup: pending` marker into `PROJECT-CONTEXT.md` (with the pointer that `project-css-setup` runs shortly before the first Section — setup does not run that pass, the design is often not final yet), and carries both as a new final-checklist gate. Scope boundary names the project-level CSS reconciliation as `project-css-setup` territory.
- `frontend-section-qa`: two-stage reaction to an unreconciled project CSS setup replaces the old "record it as a project-level finding". Stage 1 (marker): when `PROJECT-CONTEXT.md` carries `css_setup: pending`, warn once and continue when the preflight's own on-site measurement passes — no blanket stop. Stage 2 (measured mismatch): an actual measured container mismatch is a hard stop — never Section CSS that compensates for the global mismatch inside the Section; route to `project-css-setup`, the user decides whether it runs now.
- `frontend-section-qa-layout-preflight` Rule: the container fit check gains the row "measured container inner width vs the project's recorded content width" as a hard-stop condition with the same route-back to `project-css-setup`; with `css_setup: pending` the case is expected and already announced by the warn-once.
- `agent-routing` Rule: `project-css-setup` joins "Deliberately Not Routed" — it lives on interactive per-value confirmations and hard stops between its resumable blocks; a runner would either block on every value or decide global CSS values alone.
- `project-template/PROJECT-CONTEXT.md`: Project Overview gains the `Cloned from` and `css_setup` rows plus the per-block status lines; the Container Widths block is rebuilt around the derivation record (design px at the 1920 anchor, side margin, anchor rem basis, derived rem value, viewport cap, per-breakpoint overrides with reasons); new "Breakpoints & QA-Viewports" block with the breakpoint bands, rem bases, and the QA viewport ladder — a pre-existing template gap that `frontend-section-qa-tablet-band` and both QA Skills already referenced.

## Notes

- New workflow fact, previously documented nowhere in the plugin: every WESEO project starts as a **clone of a fully loaded master WordPress installation** — all Sections present, a few basic CPTs, and the master's CSS values. There is no greenfield project. "New project" therefore means "CSS values are still the master's, never reconciled with this project's design", and the Section inventory exists from day one, so the impact map applies to every project.
- Deliberately deferred (Section-level, not project setup): the asymmetric-columns warning in `wst-section-workflow` and a mandatory layout-paradigm enum in the work record (`docs/project-css-setup-plan.md`, decision 9).
- Real-project validation before promotion stays open, as with every beta-first package.
