# SmartFlow 0.7.0-beta.1

Sixth wave-1 content build: the deltas from Tobias' `cursor.zip` (Confluence page 1871085606) are melted in. Per the merge principle, only deltas are ported; `SMART-TEMPLATE-HILFE.md` stays the catalog source and the 159 individual `wst-*` catalog skills from the zip are deliberately discarded.

## Added — Skills (translated from the zip and checked against the Gesamthilfe)

- `grid-cards` (from `skills/grid-cards`): WST card templates for WP Grid Builder under `smart-template-builder/post-types/<resource>/cards/`, with the core rule that every field-reading `wst_` shortcode carries `id='{{post_id}}'`. The Gesamthilfe check confirmed the known discrepancy — the catalog names `{{post.id}}` for WPGB in three places while the working implementation uses `{{post_id}}` — so the Skill carries the open-validation note and routes resolution through the four-source proof. Workflow adapted to SmartFlow: the CPT work record replaces the handoff, CSS routes to `cpt-frontend-qa`.
- `wst-nested-shortcodes` (from `skills/verschachtelte-wst-shortcodes`): the full suffix mechanics for nesting enclosing `wst_` shortcodes — same-named nesting breaks the WordPress parser silently, nested levels get `_a`/`_b`/`_c` suffixes, `else`/`else_if` clauses inherit the suffix, negated forms keep the `!` before the base name, siblings may reuse suffixes, and self-closing shortcodes never need one. The Gesamthilfe check confirmed the suffix-skip discrepancy (the catalog nests `wst_if_b` directly inside `wst_if`); the Skill defers to the strict named-level chain of the `wst-conditional-nesting` Rule until the open validation is settled at runtime.
- `smarttags` (from `skills/smarttags`): SmartTag `{{…}}` placeholder syntax with the delta corrections from the zip — exactly one pipe with `&` chaining for multiple conversion commands, `count` as a counting flag (not a first-term limiter), and `*` as a documentation placeholder that must be replaced. The duplicated detail reference from the zip is dropped; the full command list defers to catalog section 5.24 in the `wst-shortcodes` snapshot.
- `headline-filling` (from `skills/headline-befuellung`): Format = semantic HTML tag, Style = `wso-` look class, never skip heading levels, exactly one `h1` per page; design looks that would violate the hierarchy are solved through Style, never by bending the Format.

## Changed

- `setup-local-project` absorbs the legacy `setup-wordpress-cursor` skill: new Step 8 "Expose WordPress Content Over REST" (CPT UI `show_in_rest` for post types and taxonomies, ACF field groups in REST, and the ACF options pages endpoints under `wso/v1/options/{slug}` — probed, and installed into the child theme's `js-snippets.php` as tracked source through the bundled deploy pass when missing, with the Code Snippets import as fallback). Ships `reference/acf-options-rest-endpoints.php` and the full `reference/rest-connection-test.md` (post types, sample content, options pages) adapted to the `WSO_*` variable names. Playwright MCP moves to Step 9, PROJECT-CONTEXT.md to Step 10; the new `rest_exposure` gate joins the final checklist and the cross-references in `frontend-section-qa` and `cpt-frontend-qa` are renumbered. The zip's "Astra Abilities für MCP ausblenden" snippet is deliberately not absorbed: the SmartFlow workspace calls REST directly over the shell and runs no WordPress MCP server, so there are no abilities to hide.
- `deploy-and-branches` absorbs the zip's `protected-branches` rule, adapted to the SmartFlow push model (the agent never pushes anywhere): `main`/`master`/`trunk` are additionally write-protected against commits, merges, and reverts; a `PROJECT-CONTEXT.md` that records a protected name as the working branch is a stop condition; and the prohibitions propagate explicitly into every subagent worker prompt, which may never demand a verification only a user push can satisfy.
- `wst-shortcodes` names the discard decision explicitly (the 159 per-shortcode skills are not maintained) and routes cross-cutting mechanics to the new `smarttags`, `wst-nested-shortcodes`, and `grid-cards` Skills.
