# SmartFlow 0.10.0-beta.1

Routing consolidation: the `agent-routing` Rule now covers every delegation surface in the plugin, the four execution Skills that were previously runner-backed only under package orchestration delegate their execution run to the runner on every start, and the hard model pins in the six agent files are replaced by `model: inherit` with recommended models applied through dynamic pinning at spawn — a missing model no longer breaks a spawn.

## Changed

- All six agent files (`cpt-codebase-analyst`, `cpt-figma-analyst`, `wst-shortcode-implementer`, `wpgb-specialist`, `cpt-visual-implementer`, `jira-ticket-runner`): frontmatter `model:` changed from a hard pin to `inherit`. Agents always run, by default on the main chat's model.
- `agent-routing` Rule:
  - The Model Routing table is now a **recommendation with dynamic pinning**: before the first spawn the main chat checks whether the recommended slug is available; available → passed at spawn, not available → spawn with `inherit` plus a one-sentence transparent deviation report — no blocker, no silent substitution by a third model. For the two demanding agents (`wpgb-specialist`, `cpt-figma-analyst`) the main chat flags a clearly weaker available model before the spawn; the premium escalation after one evidenced gate conflict is unchanged.
  - The trigger now also covers `grid-cards` write routing and generic worker orchestration (`auto-docs`), not only CPT packages and Jira batches.
  - New section "Deliberately Not Routed": `content`, `wp-media-import`, the setup and migration wizards, and the pure reference Skills intentionally run in the main chat — no matching agent, interactive hard stops, or lookup material. The scope decision is recorded as intentional, not a gap.
  - Runner as the standard execution vehicle: for the four runner-backed Skills (`wst-section-workflow`, `wst-new-post-type`, `frontend-section-qa`, `cpt-frontend-qa`), "one leaf is enough" means one runner, not no runner — also on direct starts.
- `wst-section-workflow` and `wst-new-post-type` Skills: the former "under package orchestration" delegation applies **on every start** — classification, pattern-discovery decision, work-record creation, and all hard stops stay in the main chat; the execution run (template and ACF JSON writes) runs through the `wst-shortcode-implementer` runner. Hard stops from inside the run come back as `OPEN DECISION` in the runner's return format; reclassification stays a main-chat hard stop.
- `frontend-section-qa` and `cpt-frontend-qa` Skills: analog — the CSS/browser-QA run executes through the `cpt-visual-implementer` runner on every start (one runner per Section or surface); deploy pass, bridge verification, and commit stay with the main chat (runners never commit). `frontend-section-qa` gains the routing paragraph it was missing (parity with `cpt-frontend-qa`); the QA semantics are unchanged.
- `grid-cards` Skill: new "Orchestration Routing" section — card-template PHP writes through the `wst-shortcode-implementer` (consistent with the `wst-php-authoring-route` Rule), WPGB grid/card configuration through the `wpgb-specialist`, card CSS with `cpt-frontend-qa` and its runner, each per the `agent-routing` Rule.
- `jira-batch-workflow` Skill: the spawning section now references the `agent-routing` Rule explicitly — model routing with the pre-spawn availability check, the fixed return contract, and the handoff schema come from the Rule instead of being restated; only the batch-specific semantics (statusboard, slots, feedback relay) stay in the Skill.
- `auto-docs` Skill: worker spawning is bound to the shared orchestration practices of the `agent-routing` Rule (self-contained prompts, parallel launches only for disjoint write targets, standing prohibitions in every worker prompt, stall stop); the workers stay generic subagents, not one of the six bundled agent definitions.

## Notes

- No new agents were added (user decision); the six bundled agent definitions are unchanged apart from the model frontmatter.
