# SmartFlow 1.4.1

Wording release, promoted from `smartflow-beta` 1.4.1-beta.1: the status bridge is now explained to the user in plain German before it is installed, and the deploy-marker file `.wso-deployed-commit` is named as a file wherever a colleague first meets it. No contract, route, or behavior changes; the bundled bridge template stays at 1.1.1, so no project needs a bridge update.

Source: Confluence idea entry `[Idee] setup-local-project: .wso-deployed-commit als Datei erklären (kein CSS-Klassenname)` (page 1976893442, Tobias Uhl, Quality Austria / qualityaustria.com.weseo.dev, plugin 1.3.0). During the Quality Austria setup the hand-over text named `.wso-deployed-commit` several times without saying it is a file; for frontend colleagues the `.wso-` shape reads as a CSS hook. Maintainer extension: the same gap existed for the bridge itself — the Skills assumed the user knows what "the bridge" is and opened with the route table. Maintainer analysis: `plugin-feedback/deployed-commit-file-and-bridge-explanation.md`.

## Changed

- **`install-status-bridge` gains "What The Bridge Is — Explain This Before Installing"**: a German explanation the agent gives before the first install step (a small PHP block in `js-snippets.php` exposing protected REST endpoints under `/wp-json/wso/v1/`, so the agent can verify that a deploy landed, flush cache and permalinks, and read/write WP Grid Builder configuration without server access; deployed like any theme file; not a plugin, no frontend change). The section pins the two easily misread names — `deployed_commit` is a field in the status response, `.wso-deployed-commit` is the plain-text marker file the deploy path writes, explicitly not a CSS class. Step 4 tells the agent to name it as a file toward the user; the checklist gets a corresponding first item.
- **`setup-local-project` Step 7** names the marker as a file at its first user-facing mention with Tobias' proposed German wording; **Step 9** opens with the plain-German bridge explanation before running `install-status-bridge`.
- **`setup-ticket-ready`**: the on-first-need row for the status bridge asks for the explanation first; the `pending: Voll-Setup` list describes `.wso-deployed-commit` as the deploy-marker file written by the installer and read by the bridge.
- **`status-bridge` Rule** opens with a one-paragraph plain-terms definition and the two-name clarification; the abort-message wording and the `deployed_commit: null` route say "the `.wso-deployed-commit` marker file".
- **`frontend-section-qa` and `cpt-frontend-qa`**: deploy-chain step and hash-mismatch abort message use the same "marker file" wording.
- Manifest descriptions of `install-status-bridge` and `status-bridge` mention the explanation.

## Notes

- Promoted by maintainer decision directly after the beta build: pure wording, no routing/deploy/bridge change. The beta twin is re-equalised and idle on `1.4.1`.
- The file name itself stays: the bridge template reads it, and a rename would be a bridge version bump plus a deploy-configuration change in every project without solving the explanation problem.
