# SmartFlow 1.3.0-beta.1

Every CPT preflight with public detail pages now has to resolve the **content model** explicitly — `typed-only`, `flexible-content-only`, or `hybrid` — before the write gate opens. The question is asked verbatim, never defaulted, and it arrives with evidence: the two analysts walk the detail design and the reference CPT and propose a model, the maintainer decides. `hybrid` (typed core plus a clone of the project's `[TMPL] Flexible Inhalte` group on the CPT post) is now a documented shape with ACF, render-order, and QA rules.

Source: a real `wso_job` foundation run in the playground project. The Job CPT was built typed-fields-only (single partial plus six ACF fields) although the Figma detail also carried page Sections around the core (Benefits slider, related Jobs grid, later an application form). Those Sections had no home on the post because the Skill never asked for a content-model decision — while `wso_reference` on the same install already used the correct hybrid/page-builder pattern (`plugin-feedback/cpt-content-model-gate.md`).

## Changed

- `wst-new-post-type` §2 asks a third mandatory preflight question whenever detail pages are yes **or** the design shows page Sections around the CPT content (Benefits, Grid, Form, Intro, …): "Should this CPT also carry Flexible Content (page-builder Sections) on the post, in addition to typed fields? Pick one: typed-only | flexible-content-only | hybrid." Detail pages no and no page Sections → `Content model: not-applicable`, not asked. The value joins the write-gate list next to `Work type`, slug, and taxonomy.
- The question is asked **with evidence, not blank**: the `cpt-codebase-analyst` states the reference CPT's content model as an explicit fact (FC clone yes/no, clone field name and clone group key as read from the install, single partial, Smart Template include) plus the existing Flexible Content layouts, and reports a dropped FC clone or a typed-only CPT facing page Sections as `OPEN DECISION`; the `cpt-figma-analyst` delivers the ordered detail-page walk with a `content-role` per segment (`typed-core` | `page-section` matched to an existing FC layout | `global` | `unresolved`) and the sandwich-order flag. The main chat derives a proposal from that and attaches it to the question; a structured-looking core is never a reason to skip Flexible Content silently.
- Three content models defined in SKILL and `reference.md`: `typed-only` (closed structured detail, no FC clone), `flexible-content-only` (the reference-CPT pattern: FC clone, no typed partial, renders via `flexible-content.php`), `hybrid` (typed fields plus single partial **and** the FC clone on the same group). The Smart Template's own Flexible Content stays empty in every model — that sentence now explicitly refers to the Smart Template post, not the CPT post.
- `hybrid` shape: clone field `wso_<resource>_content` with a fresh `field_` key, `display: seamless`, `prefix_name: 1`, clone group key read from the install (JSON shape in `reference.md` and `examples.md`); render order is the single partial first, then `[wst_include template="flexible-content.php"]` as a **sibling after** the `.wso-<resource>-single` wrapper, never nested. For `flexible-content-only` the Smart Template include is `flexible-content.php` itself. Adding the clone never retrofits `wso_` prefixes onto saved unprefixed fields.
- Design-order caveat: one FC field has one insertion point. When Figma sandwiches typed blocks and page Sections (Hero → Benefits → typed columns → Form → related grid), the work record carries the limitation; default is typed core first, then FC. No second FC field and no split typed template without an explicit maintainer decision.
- Remodel path (§3): the existing `Content model` is a protected artifact; a typed-only CPT whose design shows page Sections is flagged as a gap with a `hybrid` proposal (additive clone, saved fields untouched) instead of hardcoded includes in the single partial.
- Foundation checklist, §4.1, §4.4, §4.7, work-record list, and skeleton carry the content-model field; new Example D (hybrid `job` CPT) in SKILL and `examples.md`.
- `cpt-docs`: `content_model` frontmatter field, `Content-Modell` row in the registration table, derivation rule from the ACF JSON (clone of `[TMPL] Flexible Inhalte` present → `flexible-content-only` or `hybrid`), and the `Content model` decision added to the protected work-record sections.

## Notes

- No new agent: the two analysts already spawn on every start with a design source; their deliverables were extended rather than adding a third leaf for the same Figma file. `agent-routing`, `deploy-and-branches`, and the CSS Skills are unchanged.
- Real ACF group keys stay project values: the plugin names the `[TMPL] Flexible Inhalte` group by title and instructs to read its key from the install (the reference CPT's clone field is the precedent).
