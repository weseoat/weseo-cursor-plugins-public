# SmartFlow 0.15.0-beta.1

The agent never commits on its own anymore: every commit needs an explicit user confirmation, anchored as a hard commit gate in the `deploy-and-branches` Rule.

## Changed

- `deploy-and-branches`: new hard **commit gate** — the agent prepares every commit (files to stage, change summary, proposed message), then stops and asks for the go. Only an explicit yes authorizes exactly that one commit; a general task instruction is never commit authorization, and one confirmation never covers future commits. The single exception is a scoped standing mandate that a workflow Skill explicitly asks for and the user explicitly grants, covering only the commits that Skill names, for that run only. The subagent section now also bans commits in worker prompts explicitly (commits stay in the main chat, always through the gate), and the delivery chain reads "user-confirmed local commit".
- `jira-batch-workflow`: the "automatic per-ticket commits" with their explicit no-approval-gate design are replaced by the **batch commit mandate** — asked once at intake in German, recorded in the board header, and the only thing that lets the main chat commit a ticket as soon as its runner passes. Without the mandate, finished tickets end at the new board status `implemented` and every commit is proposed individually at the final review; a file chain then waits for the pending commit's confirmation while disjoint parallel slots keep running. Resume runs re-use the recorded mandate answer (or ask when the header carries none).
- `commit-trailer`: the trailer sentence now names the confirmation ("the agent commits with the trailer, only after the explicit user confirmation the commit gate requires, and never pushes").

## Notes

- Skills that name commit steps (deploy passes, bundled setup commits, docs commits) are unchanged on purpose: they define **when** a commit is due, the gate in `deploy-and-branches` defines **that** the user decides it happens. `setup-local-project` already carried "Stop and ask before: Any commit" as a stop condition — that behavior is now plugin-wide.
- The push ban, the protected branches, and the bundle-deploy discipline are untouched; this release only removes the agent's authority to commit unprompted.
