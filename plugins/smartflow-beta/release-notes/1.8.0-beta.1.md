# SmartFlow 1.8.0-beta.1

Release date: 2026-10-09. Beta test build on top of stable 1.7.0. The complete `code-cleanup` Skill, including structured intake and comment policy, remains in testing and is excluded from production.

The beta package contains **24 Rules, 27 Skills, and 6 agents**. The generated inventories contain 31 Claude Code Skills and 39 Codex Skills, including Rule wrappers. The non-cleanup baseline is documented in `release-notes/1.7.0.md`; this note describes the remaining beta-only scope.

## Under Test: Code Cleanup

- The recurring, behavior-preserving `code-cleanup` Skill introduced in 1.7.0-beta.1 remains available in beta with its criteria catalog, optional tooling reference, cleanup-log template, and main-chat routing. Its modes remain `post-run`, `recurring`, and `scoped`; PHP findings still use the assigned `wst-shortcode-implementer` route.
- Intake asks only for missing answers through a suitable structured question tool and reuses explicit answers for the current run. Defaults, preselected answers, or unanswered prompts are not consent. Commit mandates use an allowed permission channel for the host; without explicit consent, the mandate remains off.
- An explicit comments-only request selects Pass 3 within the agreed files. Keep explanations, constraints, workarounds, design/cascade reasons, and orientation labels. Length or a Figma reference alone is not a deletion reason. A removal-only request adds no comments and runs no unrelated declaration changes, reordering, or formatters.
- The default five-judgment budget includes comment-removal decisions. Further findings remain deferred unless the user changes that budget.
- When SCSS is authoritative, scope the source and its documented tracked CSS outputs together. Regenerate through the project build; unavailable builds defer the source/output pair, and unrelated build changes stay outside the cleanup commit without discarding foreign work.
- `cleanup_tooling`, `cleanup_hook`, and `cleanup_last_tag` are beta-only project markers while this Skill remains excluded from stable.

## Validation And Release Boundary

- The accepted intake and comment-policy changes have local scenario/consistency checks. A full cleanup run against a real project, including behavior proofs and the recurring/post-run paths, remains open; publishing this beta is not that validation.
- Do not promote cleanup merely because the other feedback changes ship in stable. Its Skill, references, routing, and metadata remain in the beta package until a separate release decision.
- The unpublished 1.7.0-beta.3 consolidation is superseded by stable 1.7.0 plus this active beta. Earlier beta notes remain historical development records.
