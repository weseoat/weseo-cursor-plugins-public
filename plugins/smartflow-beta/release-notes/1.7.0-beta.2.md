# SmartFlow 1.7.0-beta.2

SmartFlow runs in Claude Code and Codex with the same Rules, Skills, agents, and MCP servers as in Cursor, and the Cursor CLI (the way T3 Code runs Cursor) gets the Rules it silently dropped. One source, three targets: the Cursor plugin folder stays the only place where content is authored; a generator derives the Claude Code and Codex packages, and a per-user installer places the parts no plugin format can carry. Decisions and mechanics in `docs/multi-agent-targets.md`.

## Added

- **Generator `scripts/build-agent-targets.py`** (opt-in per plugin via `targets.json`). From `rules/`, `skills/`, `agents/`, and the manifests it writes:
  - Claude Code: `claude/plugins/<name>/` (`.claude-plugin/plugin.json`, `.mcp.json` with mcp-atlassian, playwright-a/b/c, figma; all Skills plus the four description-triggered Rules as `rule-*` skills; the six agents with `readonly` as `disallowedTools`).
  - Codex: `codex/plugins/<name>/` (root `plugin.json`, all Skills plus the ten conditional Rules as `rule-*` skills).
  - In both trees for the installer: `rules/*.mdc`, `claude/rules/*.md` (`globs` become `paths`, always-on Rules stay unconditional), `codex/AGENTS.md` (the twelve always-on Rules as one block), `codex/agents/*.toml` (read-only analyst as `sandbox_mode = "read-only"`), `codex/mcp-servers.toml`.
  - Nothing generated lands inside the Cursor plugin folder: Cursor reads a `.mcp.json` there and would hand Cursor users extra MCP servers. The Cursor plugin only gains `targets.json` and the installer script, both ignored by Cursor (verified).
  - Marketplaces: `.claude-plugin/marketplace.json` and `.agents/plugins/marketplace.json` at the repository root, listing every opted-in plugin.
  - `--check` fails when generated files are stale; `manage-beta.py refresh|promote` rebuilds automatically.
- **Installer `scripts/install-agent-targets.py`** inside the plugin (runs from any checkout or plugin cache): `install`, `uninstall`, `doctor`, `migrate-secrets`, `--targets claude,codex,cursor`, `--dry-run`.
  - Claude Code: `~/.claude/rules/<plugin>/` plus marketplace registration and plugin install (user scope).
  - Codex: managed block in `~/.codex/AGENTS.md`, `~/.codex/agents/*.toml`, managed block in `~/.codex/config.toml` (MCP servers with `env_vars` pass-through, plugin enable, `project_doc_max_bytes` raised because the Rules exceed Codex's 32 KiB default), marketplace registration and plugin install.
  - Cursor CLI: `~/.cursor/rules/<plugin>/*.mdc` (the CLI applies user-level rule files; plugin-cache Rules are unreliable there), and `playwright-a/b/c` in `~/.cursor/mcp.json` only when the Claude Code plugin is not installed (Cursor already loads the MCP servers of installed Claude Code plugins).
  - `migrate-secrets` moves inline Jira/Confluence values from `~/.cursor/mcp.json` into user environment variables; no file written by the installer ever contains a secret.
- **MCP servers bundled for Claude Code and Codex**: `mcp-atlassian` (`uvx`, credentials from `JIRA_*`/`CONFLUENCE_*` environment variables), `playwright-a/b/c` (`npx @playwright/mcp@latest --isolated`, the claim/release protocol applies unchanged), `figma` (remote, OAuth per agent). Cursor projects keep getting theirs from `setup-local-project`.

## Changed

- `skills/grid-cards/SKILL.md`: the description is quoted; the unquoted `Core rule: …` broke strict YAML parsers (Claude Code loaded the skill with empty metadata).
- `.claude-plugin/plugin.json` carries no `version` on purpose: Claude Code then tracks content changes of the beta channel instead of staying pinned to a number.

## Notes

- Validated on 2026-10-01 (Windows 11, T3 Code): Claude Code loads 11 always-on Rules at launch, 31 skills, 6 agents, 5 MCP servers (Playwright drives a browser through the plugin); the Cursor CLI loads the user-level Rules, the plugin Skills and agents, and the plugin MCP servers; Codex reports the plugin installed and enabled with all MCP servers registered. Codex's loaded context could not be probed headless here (CLI not logged in); verify in a T3 Code Codex thread.
- Figma needs a one-time OAuth per agent (`/mcp` in Claude Code, `codex mcp login figma`). Cursor keeps the `figma` plugin from the public marketplace.
- Glob-scoped Rules reach Codex as `rule-*` skills, not as automatic triggers; Codex has no path-scoped instructions.
- Cursor IDE users who also run the installer see the always-on Rules twice (plugin and `~/.cursor/rules`); run `install --targets claude,codex` to skip the Cursor part.
