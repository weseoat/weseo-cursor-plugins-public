# SmartFlow 1.7.0-beta.3

Status: **unpublished consolidation draft**, superseded by the selective stable 1.7.0 release scope and the cleanup-only active beta 1.8.0-beta.1 prepared on 2026-10-09. This version was not shipped as a combined beta release. The notes below preserve the consolidated development scope; they do not imply that cleanup was promoted to stable.

SmartFlow fixes the commit footer and mock-DOM proof, integrates the accepted Setup and frontend Rules, marks dispatched Jira tickets In Progress, and makes cleanup intake and comment handling explicit.

## Fixed

- **`commit-trailer`** writes the footer as a literal paragraph in the commit message: a second `-m` argument for a subject-only message, or a footer in the complete `-F` message file. The space-containing label is no longer passed through `--trailer` or `git interpret-trailers`.
- After an authorized commit, the stored message is checked for exactly one correct footer. Other trailers are preserved; a formatting mismatch does not grant permission to amend history or bypass hooks.
- The Claude Code and Codex targets are regenerated from the updated source package.
- **`cpt-frontend-qa`** checks required selectors on the authentic served DOM before injection, with bounded readiness for asynchronous output and state-specific expected counts. Missing markup returns the affected surface blocked to the main chat. Only the main chat may perform one authorized, version-checked bridge cache-recovery attempt; the recorded budget survives resumes and an uncertain POST consumes it. The runner then rechecks the same surface, never flushes caches, and leaves aggregate final status to the main chat. Known pending single assignments retain their admin hand-over; other assigned surfaces can continue independently. Synthetic DOM, replacement HTML, or an interim shim cannot establish proof.

## Added

- **`prefer-generic-over-custom`**: a theme-scoped Rule for reusing established elements, styles, and tokens while preserving explicit design requirements and Figma parity. Exceptions stay scoped and documented. The package now carries 24 Rules.

## Changed

- **`webroot-safety`** uses a task-specific, ignored `tmp/<task-name>/` directory at the Git root for temporary artifacts, preserves the OS-temp alternative and permanent documentation, and limits cleanup to the current run's own verified paths. Credentials and `.env` copies never belong in scratch output.
- **`secrets`** checks required WordPress REST variables in the shell that executes the request and reuses the project's verified environment loader. Existing session values are preserved, `.env` is not executed as code, and the agent never changes PowerShell's `$PROFILE` for this purpose. The tracked root `.env` policy remains unchanged.
- Both additions are incorporated into the existing Rules rather than creating duplicate standalone Rules.
- **`css-guideline` / `grid-cards`** centralize lowercase, single-hyphen naming for new project-owned `wso-` classes. Variants are additional classes alongside the base class on the same element. Existing hooks, third-party classes, and CSS custom properties are preserved; explicitly conflicting project conventions are resolved before new names are introduced. The grid-card Skill links the bundled Rule and uses validator-compatible wording in its description.
- **`jira-batch-workflow`** automatically applies an unambiguous In Progress transition at actual runner dispatch. Missing or ambiguous transitions are recorded without guessing; API errors or uncertain ownership block the affected row. Start evidence distinguishes this run's resumes from externally started tickets, prevents repeated transitions, and records failed spawns without automatic rollback. The optional Done transition remains separately authorized after review and comment.
- **`code-cleanup`** asks only missing intake questions through a suitable structured question tool, reuses explicit answers, and uses a separate allowed channel where the host forbids permission requests in that tool. An unanswered or preselected option never grants a commit mandate. Comments-only requests select Pass 3 within the agreed scope; explanations, workarounds, design/cascade reasons and orientation labels are preserved. Removal-only requests add no comments or unrelated formatting. Comment-removal decisions count toward the five-judgment default. Authoritative SCSS and its documented tracked CSS build outputs are scoped together; unrelated build changes are excluded without discarding foreign work. The aggressive deletion policy of `clean-css-comments` is not adopted. This entire Skill remains beta-only in 1.8.0-beta.1.

## Compatibility

- The required wording stays `Made with: SmartFlow`. Commit approval, protected branches, and push permissions are unchanged.
- Existing project-local commit helpers that copied the old `--trailer` command need the same message-format correction when their maintainer updates them. Historical commits are not rewritten automatically.
- This draft combined the in-flight changes from `1.7.0-beta.1` and `1.7.0-beta.2`. The selective release decision instead prepares the non-cleanup scope for stable `1.7.0` and retains all cleanup functionality in `1.8.0-beta.1`; publication is recorded separately.
