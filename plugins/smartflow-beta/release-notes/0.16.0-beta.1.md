# SmartFlow 0.16.0-beta.1

WP Grid Builder grids, cards, and facets are now readable **and writable** over the status bridge: bridge version 1.1.0 adds `wso/v1/wpgb/*` routes, and the `wpgb-specialist` uses them as the standard write route once a project has validated them — apply-specs for the admin remain the fallback.

## Added

- **Bridge template 1.1.0** (`install-status-bridge`): five new routes behind the existing `manage_options` check — `GET /wpgb/<type>` (list grids/cards/facets), `GET /wpgb/<type>/<id>` (full configuration as decoded, exporter-compatible JSON), `POST /wpgb/<type>` (create, with name/slug collision check, response carries the new id), `POST /wpgb/<type>/<id>` (update with the same payload shape the GET returns), and `POST /wpgb/reindex` (facet indexer, all facets or one via `facet_id`). The routes wrap WPGB internals (`Database::save_row()`/`query_row()`, exporter, indexer) behind `class_exists` guards and answer with a clear error plus `wpgb_version` when the internals are missing or drifted. Additive change, no breaking change; the normal update path rolls 1.1.0 out to existing projects automatically.
- `status-bridge` Rule: new **"WPGB Read/Write"** section — read-modify-write always (GET first, minimal diff, full payload back), every write proven by a re-read, name/slug uniqueness before create, card before grid, reindex after facet writes, cache flush after write passes; plus the extended routes table and error handling for pre-1.1.0 bridges and drifted WPGB internals.
- `wpgb-specialist`: new **create workflow** — clone the precedent grid/card per GET, apply the design diff, POST without id, write the new id back into the work record and to the shortcode integration; facet creates end in a reindex.

## Changed

- `wpgb-specialist`: the `wso/v1/wpgb/*` routes are **the** standard write route when both gates hold — bridge >= 1.1.0 installed and `PROJECT-CONTEXT.md` records the WPGB bridge write route as project-validated. The existing gate stays: no silent default flip before the test-project validation; without it, the admin apply-spec remains the delivery. The ban on direct database writes is unchanged — the bridge route is the allowed way, never `$wpdb`.
- `install-status-bridge`: routes table extended by the five WPGB routes; the marker-based update path works unchanged.
- `wst-new-post-type`: the WPGB apply-spec delivery path now names the bridge write route as the validatable alternative (same gates).
- `grid-cards`: the orchestration routing notes that the `wpgb-specialist` can create and update grids/cards over the bridge when the route is validated.

## Notes

- The write routes rest on **undocumented WPGB internals** (reference: `AmphiBee/wpgb-extended`). After a WP Grid Builder plugin update they are the first suspect when WPGB work starts failing; the routes report `wpgb_version` for drift diagnosis.
- This release settles the technical side of the open WPGB write-route validation; the acceptance step remains the test-project run (update, create, and reindex cases over the new routes, verified in admin and frontend).
