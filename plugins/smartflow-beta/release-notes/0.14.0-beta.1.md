# SmartFlow 0.14.0-beta.1

Two policy changes: the Atlassian MCP team standard flips from the official Rovo server to the community `mcp-atlassian` server (version 0.22.0 or newer, security-reviewed), and CPT ACF field names now always carry the `wso_` prefix.

## Changed

- **Atlassian MCP team standard is now the community `mcp-atlassian` server** ([sooperset/mcp-atlassian](https://github.com/sooperset/mcp-atlassian)), version 0.22.0 or newer. The Rovo surface proved too limited (12 Confluence tools, no labels, no attachments, whole-body page update only); the community server carries the full Jira and Confluence tool surface. An already working Rovo server stays a functioning read variant, but every new install is guided to the community server.
  - `setup-local-project`: Step 5 is now the community `mcp-atlassian` preflight — install route over the user-level `mcp.json` with `uvx`, the version floor enforced in the server spec (`uvx --from "mcp-atlassian>=0.22.0" mcp-atlassian`), local stdio transport only (never the HTTP/SSE transports), and the API token in the `env` block, never in `args`.
  - `confluence-source`, `smartflow-feedback`, `sync-project-brief`: the community tool names are now the primary mapping; the Rovo names stay documented as the legacy variant. The intake design (metadata block, text-only entries, maintainer-owned curation) is deliberately unchanged even though the community server has label and attachment tools.
- **CPT ACF field names always carry the `wso_` prefix**: every new field in a CPT field group is named `wso_<resource>_<field>` — a salary field on a Job CPT is `wso_job_salary`, never `job_salary` or `salary`. Anchored in the `acf-local-json` Rule (Keys, Names, And Filenames) and in `wst-new-post-type` (Step 4.4, reference, examples). Retrofitting the prefix onto already saved unprefixed fields is a data migration requiring an explicit user decision — never a casual rename.

## Notes

- The version floor 0.22.0 is a security requirement, not a preference: versions below 0.17.0 carry a chained SSRF and path-traversal RCE (CVE-2026-27826, CVE-2026-27825), and only 0.22.0 closed the remaining audit findings (attachment path traversal / arbitrary file read incl. env-credential exfiltration CVE-2026-73498, DNS rebinding, unauthenticated HTTP transport credential fallback). The published attack chains target HTTP deployments — the SmartFlow setup runs the server locally over stdio only.
- The Rovo live check from the Confluence integration plan is closed as obsolete: the Rovo server was never installed in any workspace, while the community server has been running productively as the maintainer MCP since the integration shipped. Decision log: `docs/confluence-integration-plan.md`, amendment 2026-09-02.
