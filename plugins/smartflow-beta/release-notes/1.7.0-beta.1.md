# SmartFlow 1.7.0-beta.1

New Skill `code-cleanup`: a recurring, behavior-preserving cleanup pass over child-theme code (WST PHP templates and partials, section and CPT CSS/SCSS, theme snippets, ACF Local JSON as audit only) — the counterweight to the duplication and drift that agent-written code accumulates when nobody tidies. Built from a web research pass (2026-09-25) over the current WordPress coding-standard tooling, the leading AI-agent cleanup/simplify skills, WordPress/Astra/ACF convention sources, and the recurrence mechanisms that fit a workspace where the agent never pushes and a human confirms every commit.

## Added

- **New Skill `code-cleanup`** (26th Skill; main chat by design, recorded in `agent-routing` "Deliberately Not Routed"):
  - **Three modes.** `post-run` on the files a Section, CPT, ticket, or content run just touched (uncommitted changes as scope); `recurring` (default weekly, ≤ 60 min) over everything changed since the last `cleanup/<date>` tag plus the top-3 hotspots of the last 90 days; `scoped` on a named Section, CPT, file, or folder. Never widens the scope silently.
  - **Six ordered passes, safest → riskiest**, each proof-baselined, applied, verified, scope-checked (`git diff --stat`) and committed on its own (`cleanup(<pass>): …`, SmartFlow trailer): 1 Format (mechanical), 2 Leftovers (debug calls, commented-out code, unused variables, unconsumed custom properties, unreferenced partials/files as **candidates**), 3 Comments and filler (narration comments out, every "why" stays), 4 Conventions (`wso-`/`wso_` patterns, prefixes, late escaping, tokens over hardcoded values, `!important`/specificity, media-query direction, WST nesting suffixes, style-loader registration; ACF JSON report-only), 5 Duplication → reuse via the deletion ladder (delete → reuse existing token/utility/partial → platform function → simplify in place), 6 Simplification (guard clauses, over-defensive checks, pass-through wrappers; one finding at a time).
  - **Hard rules.** Behavior preserved (a proof diff decides, not confidence); one pass per commit; scope locked with out-of-scope findings reported, never drive-by fixed; skip when in doubt; never renames of `wso-` hooks, ACF names/keys, functions, hooks, or files, never file moves, never new abstractions or dependencies, never `!important` shuffles, never ACF structural writes, never `functions.php`, `theme-functions.php` / bridge block only with the `file-edit-boundary` confirmation; budget of 5 judgment findings and 60 minutes per run (rest → ledger); not before a deploy, not mid-feature.
  - **Proof without tests.** CSS: Playwright screenshots of the affected surfaces (preview URL or served page) at the project's QA rungs before, injection-proof plus screenshots and computed styles after; deletions additionally need the reference search or CSS coverage across the full ladder and states (never coverage alone for state classes). PHP: normalized HTML snapshot of the rendered Section/single before and after with an empty diff; escaping changes are shown and confirmed, never assumed harmless. Unreachable proof = `deferred`, never an unproven change.
  - **Conventions precedence.** `docs/coding-standard/<language>.md` (from `auto-docs`) → bundled Rules (`css-guideline`, `wordpress-brand-tokens`, `wst-conditional-nesting`, `wst-php-authoring-route`, `acf-local-json`, `headline-filling`, `file-edit-boundary`, `webroot-safety`) → WordPress handbook as default. A documented project deviation (short arrays, non-Yoda) is a convention, not a finding; silent conventions are recorded as open, never enforced by guess.
  - **Intake commit mandate.** The per-run "Cleanup-Commit-Mandat" (default no) is the scoped standing mandate the `deploy-and-branches` Rule allows a Skill to ask for: it covers only the pass commits of that run, never a push; without it every pass commit is proposed individually; in the legacy state `Working branch: master — user commits` the agent only prepares.
  - **Close-out.** Deploy hand-over with hard stop and bridge verification (`implementation pass, deployed verification pending` until then), local tag `cleanup/<date>` as the next scope anchor, ledger `docs/cleanup-log.md` (bundled template: per-run table, deferred, rejected with reason, recurring counts, open conventions), and a convention proposal when a finding recurs three times (sentence for `docs/coding-standard/`, optionally a `smartflow-feedback` proposal — user decides).
  - **Recurrence model.** Post-run offer after every run → optional staged-files pre-commit check chained with the existing ACF pull hook (`cleanup_hook`) → weekly recurring run on a calendar reminder. Unattended cloud schedulers (Cursor Automations, vendor routines) push branches or open PRs and are documented as report-only at most; `/loop` is session-bound and not a scheduler.
  - **Bundled references.** `reference/criteria-catalog.md` (criteria by pass and file type with IDs, `[auto]/[judgment]` and `[safe]/[confirm]` tags, detecting tool, the AI-code smell checklist, the safety rails), `reference/tooling.md` (opt-in tooling ladder with the September-2026 pins — WPCS 3.4.1 requires PHPCS 3.13.x, PHPCompatibilityWP 2.1.x stable, stylelint 17 vs `@wordpress/stylelint-config` on 16 — minimal `phpcs.xml.dist` tuned for WST templates, `stylelint.config.mjs`, `.editorconfig`/`.gitattributes`, `acf-lint`, pre-commit chaining snippet, Cursor `afterFileEdit`/`stop` hook caveats on Windows, the recurrence fit table, scope and ledger commands), `templates/cleanup-log.md`.

## Changed

- `agent-routing` "Deliberately Not Routed" lists `code-cleanup` with the reason (per-finding decisions, per-pass commit gate, proofs the user sees; only the read-only audit of a large scope may go to generic worker subagents). Accepted PHP findings are applied by `wst-shortcode-implementer` in an apply-only spawn per pass (exact finding list, exact PHP write scope, no commits), so the `wst-php-authoring-route` Rule holds — the main chat writes CSS/SCSS, docs, and the ledger only.
- `project-template/PROJECT-CONTEXT.md` gains the marker rows `cleanup_tooling` (`none | phpcs | phpcs+stylelint | phpcs+stylelint+editorconfig`), `cleanup_hook` (`none | pre-commit (report) | pre-commit (fix)`), and `cleanup_last_tag`.

## Notes

- Tooling is never installed inside a cleanup run; the opt-in setup (Composer/npm at the repository root, outside the deploy path) is a confirmed step recorded in `PROJECT-CONTEXT.md`. Without tooling every criterion runs as an agent check.
- The Skill is distinct from the backlog "Clean-up Skill" (workspace cleanup against the plugin contract, retained work records after Go-Live) — that remains a separate maintainer concern.
- No routing, deploy-chain, or bridge contract change; the bridge template stays 1.1.1. Real-project validation of the post-run and recurring modes is open before promotion.
