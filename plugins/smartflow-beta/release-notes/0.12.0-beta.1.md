# SmartFlow 0.12.0-beta.1

Confluence integration in two streams: Confluence becomes the leading source for project implementation facts, and the SmartFlow Confluence area becomes a team feedback hub operated from Cursor. Decision log: `docs/confluence-integration-plan.md` (grill-me interview 2026-08-25).

## Added

- `confluence-source` Rule: the project lead's Confluence "Umsetzung" page is the leading input source, anchored once in `PROJECT-CONTEXT.md` (page ID, URL, mirror timestamp) and read at exactly three points — setup mirrors the extract, the four work-package Skills re-read fresh at run start, and runners stay offline with the distilled extract in their worker prompt. Extraction instead of template enforcement (optional text status markers `OFFEN:`/`ENTSCHIEDEN:`/`ENTFÄLLT:` and the "Für Cursor" header block recognized when present), no anchor is a valid state with a clean skip, and secrets are never mirrored — placeholder plus pointer instead.
- `feedback-capture` Rule (always-on): when a run step demonstrably deviated from a bundled Skill's or Rule's promise, the agent offers a one-line report at the hand-over point and runs `smartflow-feedback` on yes. Hard annoyance guards: only real detected deviations, one sentence, never blocking, never mid-run, once per deviation, never auto-report.
- `smartflow-feedback` Skill: report bugs, questions, improvement ideas, and skill/rule proposals to the Confluence feedback hub from the working chat. Four entry types with session autofill for the bug case (the reporter never provides structure, only a yes), hard redaction rules, confirmation-gated duplicate search over CQL (never auto-attach), German entry subpages with the fixed structure and a plain-text metadata block replacing labels (the Rovo MCP has no label or attachment tools), occurrence/regression comments that never change status, and the Technischer Anhang as the maintainer handoff. Hub page IDs ship as a bundled reference, re-verified 2026-08-26.
- `sync-project-brief` Skill: the controlled refresh point when the PL page changes after setup — re-read the anchored page, show an impact-grouped diff against the `PROJECT-CONTEXT.md` mirror (naming affected work records), and overwrite only after user confirmation. Never silently, never mid-work.

## Changed

- `setup-local-project`: Step 5 is now the Rovo preflight — the official Atlassian Rovo MCP (Cursor marketplace install, OAuth) is the team standard for new installs, a working community server stays a valid variant, and API tokens in MCP `args` are flagged as an anti-pattern. New Step 6 anchors the project's Confluence page and mirrors the extract into `PROJECT-CONTEXT.md` (no page is a valid state); later steps renumbered to 7–13, and the `confluence_anchor` gate joins the final checklist.
- `wst-section-workflow`, `wst-new-post-type`, `figma-page-builder`, `jira-ticket-workflow`: each run starts with a fresh read of the anchored Confluence page and pulls only the work-package-relevant section (task row, notes, Figma link) into the work record or run context; clean skip with `confluence-source: no anchor` (or `MCP unavailable`) when the read is not possible. Runners keep receiving the distilled extract in their prompt and never call Confluence.
- `agent-routing` Rule: `smartflow-feedback` and `sync-project-brief` join the "Deliberately Not Routed" list — both are interactive main-chat Skills, and runners never call Confluence per the `confluence-source` Rule.
- `project-template/PROJECT-CONTEXT.md`: new "Confluence Project Source" block (page ID, URL, mirror timestamp, anchor gate, mirrored extract table) after "Setup And Access Policy".
