# SmartFlow 0.8.0-beta.1

ACF field definitions move from the PHP field-group model to **Local JSON with sync**. The workflow was proven and productively accepted at `anton-llm-playground.at.weseo.dev` (2026-08-19): the admin stays editable for colleagues, agents get a tracked write path in the repository, and a human confirms every structural change with a sync click. The PHP migration scaffold (full PHP export plus deletion of the database groups) is retired because it removed admin field editing.

## Added

- `acf-local-json` Rule (replaces `acf-php-field-groups`): all project-owned ACF field definitions live as one JSON file per group under `themes/<child-theme>/acf-json/`; ACF detects the folder automatically (no `functions.php`/`theme-functions.php` wiring). Both directions are defined — admin saves flow to the repo over read-only FTP, repo changes flow to the admin over deploy plus a human-confirmed sync. Binding operating rules: **pull-before-deploy** (complete `acf-json/` listing over read-only FTP before every deploying commit), JSON files as the **only agent write path** for definitions (structural ACF database writes stay forbidden entirely), the `modified` bump for sync detection, and "sync only after diff review" as the team rule. Carries the proven pitfalls: the ACF Extended `acfe_autosync` opt-in, the per-installation filename convention (determined empirically; key duplicates can shadow fresh files), deploy removal verification, and hash-based (never timestamp-based) FTP comparisons. Plugin-registered PHP groups (`local: "php"`) do not take part and are never edited.
- `setup-acf-local-json` Skill: the guided one-time setup — bridge inventory (`local: false` participants), `acf-json/` creation, seed split from a user-driven ACF admin export (PHP `json_encode` style, no `modified` in seeds, keys reconciled against the inventory), the ACFE opt-in fix with a one-time collective sync, empirical filename-convention determination, both-direction functional proofs, and acceptance over an FTP hash comparison plus the bridge listing all participants as `local: "json"`.

## Changed

- `migrate-ssh-to-local`: the destructive ACF core of the migration is gone. Stage 1 no longer exports field groups to PHP and no longer deletes the database groups; it only takes the ACF admin JSON export as the Local JSON seed source. The import stage gains the ACF Local JSON setup (new step 2.5, via `setup-acf-local-json`); acceptance now expects the project groups as `local: "json"`.
- `wst-section-workflow` (+ reference): Section field groups and the Flexible Content layout/clone-child wiring are authored as JSON in `acf-json/` (JSON shapes in the reference, `acfe_autosync` and `modified` required). The deploy pass gains pull-before-deploy and a new hand-over step: field-definition changes are live only after the human sync in the admin; the bridge check expects `local: "json"`. The stop condition "FC container still admin-created" now routes to `setup-acf-local-json` instead of the retired PHP migration.
- `wst-new-post-type` (+ reference): the CPT field group is a JSON file in `acf-json/` (JSON shape in the reference); the deploy pass gains pull-before-deploy and the human-sync hand-over; verification expects `local: "json"`.
- `auto-docs` / `cpt-docs`: ACF field-group documentation is generated from the JSON sources under `acf-json/`; legacy PHP field groups and admin JSON exports remain as fallbacks for not-yet-migrated projects. Templates reference the JSON files and the `local: json` bridge check.
- `section-preview-harness`: expanded clone field names are derived from the ACF JSON sources (or the fixture export route).
- `file-edit-boundary`: the editable ACF path is now `themes/<child-theme>/acf-json/`; `deploy-and-branches`, `wordpress-content-editing`, `wst-php-authoring-route`, `agent-routing`, and the `frontend-section-qa`/`cpt-frontend-qa` ownership statements reference the JSON model.
- Agents (`cpt-codebase-analyst`, `wst-shortcode-implementer`, `cpt-visual-implementer`): discovery paths and write scopes now name the `acf-json/` files and the `acf-local-json` Rule.

## Removed

- `acf-php-field-groups` Rule. Its non-negotiable core — structural ACF database writes are forbidden, stable fresh keys, key/name changes are data migrations — lives on unchanged in `acf-local-json`.

## Notes

- Decision basis: the PHP model disabled admin field editing, which is unacceptable for projects where colleagues maintain fields in the admin. The alternatives (full PHP migration; read-only JSON mirror outside the deploy path) were evaluated and rejected in the source project; Local JSON with sync kept both the admin and the agent write path. Details in `plugin-feedback/acf-local-json-workflow.md`.
- The status bridge already reports `local: "json"`; the bundled bridge template is unchanged (no bridge version bump).
- The open validation "ACF field groups fully in PHP" is closed as rejected in the development repository; projects already migrated to PHP field groups keep working but should adopt Local JSON deliberately (the legacy PHP sources remain readable fallbacks in the docs Skills).
