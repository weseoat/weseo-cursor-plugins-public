# SmartFlow 1.7.0

Release date: 2026-10-09. This selective stable release takes the non-cleanup changes from the beta channel. The complete `code-cleanup` Skill and its intake/comment-policy changes remain in `smartflow-beta` 1.8.0-beta.1 for testing.

The stable package contains **24 Rules, 26 Skills, and 6 agents**.

## Added

- **Claude Code, Codex, and Cursor CLI support** from the multi-agent work introduced in 1.7.0-beta.2. The Cursor package remains the authoring source; `targets.json` opts stable SmartFlow into the existing generator. Generated packages carry the corresponding Rules, Skills, agents, MCP configuration, and per-user installer assets. The installer provides the Rules and agents that the native plugin formats cannot carry and keeps credentials in environment variables.
- **`prefer-generic-over-custom`** reuses established theme elements, styles, and tokens where they meet the requirement. Explicit user and Figma requirements remain binding; necessary additions stay scoped and documented.

## Fixed

- **`commit-trailer`** writes exactly `Made with: SmartFlow` as a literal commit-message paragraph, using a second `-m` argument or the complete `-F` message file. The space-containing label no longer passes through the Git trailer parser. The stored message is checked after the authorized commit; other trailers and history protections remain intact.
- **`cpt-frontend-qa`** checks the authentic served markup before CSS injection or proof. Evidence includes the resolved URL, required selectors, expected/observed counts, and the pre-injection DOM. Bounded readiness checks account for asynchronous output; a legitimate empty filter state does not prove absent card styling.
- Missing required markup returns a **blocked surface to the main chat**. Only the main chat may perform the single authorized, version-checked bridge cache-recovery attempt; its recorded budget survives resumes, and an uncertain POST consumes the attempt. The runner then rechecks the same surface against the real page. It never flushes caches or changes the aggregate final status for this finding. Known pending single-template assignments keep their specific admin hand-over. Independent surfaces can continue through their own runners.
- Synthetic markup, local replacement pages, intercepted HTML, and interim shims cannot establish proof. CSS injection into authentic served markup remains the normal implementation proof; deployed verification stays separate.

## Changed

- **`webroot-safety`** uses an ignored, task-specific scratch directory at the Git root or the OS temp directory. Only the current run's own verified artifacts are removed; permanent documentation and retained QA evidence stay intact. Scratch output never contains credentials or `.env` copies.
- **`secrets`** checks WordPress REST variables in the shell executing the request and loads missing values through the verified project route. Existing session values remain intact. The agent neither executes `.env` as code nor changes a persistent PowerShell profile; the deliberately tracked root `.env` remains unchanged.
- **`css-guideline` / `grid-cards`** centralize lowercase, single-hyphen names for new project-owned `wso-` classes. A variant is an additional class on the same element alongside its base class. Existing hooks, third-party classes, and CSS custom properties remain intact. Explicitly conflicting project conventions are resolved before introducing new names. `grid-cards` references the bundled Rule and uses strict-YAML-compatible metadata.
- **`jira-batch-workflow`** automatically applies a unique In Progress transition at actual runner dispatch. Missing or ambiguous transitions are recorded without guessing; API failures or uncertain ownership block the affected row. Recorded run/start evidence prevents duplicate transitions or starts on resume and excludes externally started tickets. A failed runner spawn is documented without an automatic status rollback. The optional Done transition still requires its separate authorization after review and comment.

## Compatibility And Validation

- This is a selective promotion, not a full promotion of 1.7.0-beta.1 or 1.7.0-beta.3. Stable does not bundle or route to `code-cleanup`; the beta retains it and its references.
- Run either `smartflow` or `smartflow-beta`, never both, and uninstall the six legacy packages when switching to SmartFlow.
- Claude Code and Codex generated packages remain in the private repository. The existing public mirror distributes the Cursor packages; its allowlist is unchanged. The generated stable inventories contain 30 Claude Code Skills and 38 Codex Skills, including the applicable Rule wrappers.
- Commit approval, protected branches, push permissions, the deploy chain, and status-bridge requirements remain unchanged. Existing project helpers using the old trailer-parser command need their own authorized correction; historical commits are not rewritten.
- Local text/scenario and package checks do not constitute a live WordPress, Jira, or installation smoke test. The earlier Claude Code/Cursor CLI evidence from 2026-10-01 remains historical; fresh release-install smoke checks and the previously open Codex loaded-context check remain to be recorded.
