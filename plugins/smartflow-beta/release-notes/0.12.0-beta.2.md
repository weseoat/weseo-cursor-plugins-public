# SmartFlow 0.12.0-beta.2

Consistency fixes around the Section preview harness integration and one leftover from the Local JSON switch (0.8.0-beta.1). No behavior change to the harness itself.

## Fixed

- `wst-section-workflow`: the new-Section checklist still carried two pre-0.8 steps ("Create the PHP Section field group", "PHP FC container") that contradicted the Skill body and the `acf-local-json` Rule. Both steps now name the Local JSON authoring: the Section group is a JSON file under `acf-json/` (fresh stable keys, `acfe_autosync` includes `"json"`, `modified` bump), and the Flexible Content layout plus clone child are added in the FC container's JSON file with its own `modified` bump.

## Changed

- Harness offer ownership made explicit across the three delegation surfaces. Since 0.10.0-beta.1 the Section execution run is delegated to the `wst-shortcode-implementer` runner on every start, but the runner may neither spawn subagents nor touch `theme-functions.php` — exactly what the harness bootstrap needs. The wiring is now spelled out: `wst-section-workflow` says at the offer point that the main chat runs `section-preview-harness` itself (the former "run as a sub-flow" wording is gone) and that an offer surfacing inside a runner execution returns as `OPEN DECISION`; the `agent-routing` "Deliberately Not Routed" section states the same rule from the routing side; the runner's Never-list names the harness setup and its files explicitly.

## Notes

- Historical release notes and the deliberate legacy fallbacks in `auto-docs`/`cpt-docs` (PHP field groups as read sources for not-yet-migrated projects) are unchanged on purpose.
