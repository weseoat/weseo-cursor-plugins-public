# SmartFlow 0.5.0-beta.1

Fourth wave-1 content build: the WST workflow Skills and the shortcode catalog entry.

## Added — Skills

- `wst-section-workflow` (rewritten from the legacy wst-builder Skill for the single wp-content-level workspace): classification (new foundation, remodel, visual-only) with the reclassification stop, pattern discovery with the four-source proof for every new WST shortcode form, Section artifacts authored entirely as tracked source — template, PHP ACF field group with fresh stable keys, Flexible Content layout and seamless clone child in the PHP-registered container (`parent_layout` binding), `flexible-content.php` registration — one bundled deploy pass (commit with trailer, hard stop, user pushes, bridge-verified `deployed_commit`), served verification limited to function and existence, content row plans handed to the user for the admin, the Section preview pages offer/use flow, and the Section work record in the project docs layer (Visual QA Targets matrix, Frontend QA Brief) that routes to `frontend-section-qa`. The legacy handoff lifecycle, the Remote-SSH phase split, and the ACF structural write gate are gone; structural ACF database writes are forbidden entirely per `acf-php-field-groups`.
- `wst-new-post-type` (rewritten for the single workspace): preflight as write gate producing the CPT work-record draft, three delivery paths — tracked source (card/single templates, PHP ACF field group) over the bundled deploy pass; CPT UI, taxonomy (per `wordpress-taxonomies`), and WP Grid Builder apply-specs prepared for the user with `GET /status` readback of generated IDs; bridge flushes for permalinks and caches — remodel protections, the `{{post.id}}` vs `{{post_id}}` card-placeholder caution as an open validation, and the CPT work record in the docs layer that routes to `cpt-frontend-qa`. The legacy `grill-me` dependency and the CPT handoff template are replaced by the inline preflight and the work record.
- `section-preview-harness` (migrated from the proven wst-builder 0.3.0 pilot version, adapted to the shell-less workspace): the proven reference implementation ships unchanged in its render path (virtual route, query-lifecycle hardening, `acf_setup_meta()` fixtures, Astra assumption, QA hooks), while the WP-CLI fixture exporter is replaced by a gated REST export route (`GET /wp-json/wso-preview/v1/export/<section>`, `manage_options`) whose fixtures the agent writes into the repository; rewrites are flushed through the status bridge, fixtures deploy with the child theme, and preview URLs count only after a bridge-verified deploy. `REFERENCE.md` carries the adapted export/prefill mechanics; expanded clone names are now derived from the PHP field-group sources or the export route.
- `wst-shortcodes` (new): entry point into the bundled Smart Template Gesamthilfe snapshot (`reference/SMART-TEMPLATE-HILFE.md`, exported 2026-07-16, Smart Template 6.19.4 / Builder 1.6.2, ~394 KB, targeted section loads only — never the whole file), owner of the four-source proof (catalog, installed runtime, project precedent, rendered HTML; runtime evidence wins on conflict) required by the WST workflow Skills and gated by the `wst-shortcode-implementer` runner, and the documented open catalog discrepancies (`{{post.id}}` vs `{{post_id}}` in WPGB cards; the conditional suffix chain, where the `wst-conditional-nesting` Rule wins until runtime validation).

## Notes

- The catalog follows the deltas-only merge principle: `SMART-TEMPLATE-HILFE.md` is the single catalog source; the 159 individual per-shortcode skills from the legacy zip are deliberately not ported.
- Open runtime questions touched by these Skills (ACF fully in PHP, the WPGB card placeholder, the conditional suffix chain, WPGB writability without the admin) are tracked as open validations in the development repository.
- The frontend workflow Skills (`frontend-section-qa`, `cpt-frontend-qa`, `setup-playwright-mcp`) and the Commands land in the remaining wave-1 and wave-2 migrations of the SmartFlow rework plan; the new work records already name them as routing targets.
