# SmartFlow 1.0.0

First stable release. SmartFlow is the complete WESEO WordPress/WST workflow in one plugin and officially replaces the three frozen legacy plugins (`wst-builder`, `frontend-design-qa`, `wordpress-server-ops`) and their retired `-beta` twins. Promoted from `smartflow-beta` 0.16.0-beta.2 after the beta line 0.2.0-beta.1 through 0.16.0-beta.2.

## What SmartFlow 1.0.0 contains

21 Rules, 25 Skills, and 6 subagents covering the full workflow chain: Figma/brief -> local wp-content-level repository -> user-confirmed commit with hard stop -> the user pushes -> child-theme deploy -> status bridge verification -> injection-proofed Playwright QA -> work records in the project `docs/` layer.

Highlights of the beta line that ships stable here:

- **Local workspace model** (0.2.0 - 0.7.0): the local wp-content-level repository replaces Remote-SSH; the agent never pushes and — since 0.15.0 — never commits without an explicit user confirmation; `weseo-git-installer` deploys only the child theme; handoff files dissolve into the project `docs/` layer (`auto-docs`/`cpt-docs` work records).
- **Status bridge `wso/v1`** (template 1.1.1): deploy verification (`deployed_commit`), cache and permalink flush, and — since 0.16.0 — full WP Grid Builder read/write routes (list, read, create, update, reindex), validated live on WPGB 2.3.2.
- **ACF Local JSON** (0.8.0): field groups live as JSON under `acf-json/` in the child theme — admin stays editable, agents write JSON with a `modified` bump, a human confirms every structural change with a sync click. Structural ACF database writes stay forbidden. CPT field names carry the mandatory `wso_` prefix (0.14.0).
- **Six subagents with always-on routing** (0.9.0/0.10.0): `cpt-codebase-analyst`, `cpt-figma-analyst`, `wst-shortcode-implementer`, `wpgb-specialist`, `cpt-visual-implementer`, `jira-ticket-runner`; recommended-model routing with dynamic pinning at spawn; classification, hard stops, deploy pass, and commits stay in the main chat.
- **Workflow Skills**: `wst-section-workflow`, `wst-new-post-type`, `frontend-section-qa`, `cpt-frontend-qa`, `figma-page-builder`, `jira-ticket-workflow`, `jira-batch-workflow` (with batch commit mandate), `project-css-setup`, `section-preview-harness`, `grill-me`, and the setup wizards (`setup-local-project`, `setup-acf-local-json`, `migrate-ssh-to-local`, `install-status-bridge`).
- **Confluence integration** (0.12.0): Confluence as the leading project source (`confluence-source`, `sync-project-brief`, anchored page reads in the work-package Skills) and the feedback hub (`smartflow-feedback`, `feedback-capture`). Team standard is the community `mcp-atlassian` server, version 0.22.0 or newer (0.14.0), with local stdio transport and the token only in the `env` block.

## Hard switch

Installing `smartflow` requires uninstalling all legacy packages — the three legacy stable plugins and any legacy `-beta` twin. There is no mixed operation: running SmartFlow next to a legacy package produces duplicate and partly contradictory rules and skills. Within the successor pair, run `smartflow` or `smartflow-beta`, never both.

## Notes

- The full beta history lives in `release-notes/0.*.md`; `docs/plugin-changelogs.md` carries the readable summary.
- Project-specific values stay in the project-local `PROJECT-CONTEXT.md` and the project `docs/` layer, never in the plugin.
- Some beta-first features still carry open real-project validations (tracked in `docs/open-validations.md` and `WORK_PROGRESS.md`); they ship stable with the known-open items documented there.
