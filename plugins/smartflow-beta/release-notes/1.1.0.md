# SmartFlow 1.1.0

The two analysts leave the undefined "package orchestration" gate: the `cpt-codebase-analyst` supplies the `wst-new-post-type` preflight evidence on every start, the `cpt-figma-analyst` spawns whenever a design source exists, and the `agent-routing` Rule now defines the package vocabulary so no routing statement hangs on an untriggerable mode. Promoted from `smartflow-beta` 1.1.0-beta.1.

## Changed

- `wst-new-post-type` preflight: the leftover "Under package orchestration, the `cpt-codebase-analyst` and `cpt-figma-analyst` supply this evidence" was the last stale conditional from before the always-on routing (0.10.0-beta.1 converted the runners, 0.12.0-beta.3 the `wpgb-specialist`) — the condition was never defined or triggered anywhere in the plugin, so the analysts were dead code and the main chat ran the discovery inventory inline. Now the `cpt-codebase-analyst` supplies the preflight evidence on every foundation or remodel start; the only skip is a checkable cheap path: a verified reference baseline and Project Layout Profile already recorded in the docs layer or `PROJECT-CONTEXT.md`, in which case the main chat reads only the delta from those records. The `cpt-figma-analyst` spawns whenever the source brief carries a design reference; without a design source it has nothing to extract and does not spawn. The routing paragraph names both analysts alongside the runner and the `wpgb-specialist`.
- `agent-routing`: new "Packages" section defines the previously undefined vocabulary — CPT package (one CPT across its surfaces), package run (more than one surface in one task), package manifest (the decomposition record of Orchestration point 1, which now explicitly includes the assigned write scope) — and states that package orchestration is not a separate mode: every routing statement applies on every start, single-surface direct starts included. Orchestration point 1 records when the two analysts spawn.
- `wst-section-workflow`: routine single-Section discovery deliberately stays in the main chat — one reference Section and one design frame do not justify a discovery leaf — with heavy Figma extraction (pixel-parity targets, genuinely complex new components) delegated to the `cpt-figma-analyst` per its agent file; the `cpt-codebase-analyst` stays CPT-package-scoped. Recorded as intentional, not a parity gap.
- `cpt-codebase-analyst`: the description names the concrete trigger (the `wst-new-post-type` preflight on every foundation or remodel start, with the recorded-baseline skip) instead of the vague "during discovery".

## Notes

- Verified and deliberately unchanged: the "not only under package orchestration" contrast phrases in the four execution Skills stay correct and now resolve against the new Packages definition; `figma-page-builder`'s deliberate `explore` choice still holds (page composition needs a broad, light install inventory, not CPT-package analysis); the `cpt-figma-analyst` description already carried the unconditional wording ("Use when design facts for a CPT package or Section must be extracted from Figma"); `sync-project-brief`'s "work-package run" is a different term (a run of one of the work-package Skills); historical release notes stay as they are.
