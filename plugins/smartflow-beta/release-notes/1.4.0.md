# SmartFlow 1.4.0

Two things ship in this stable release, promoted from `smartflow-beta` 1.4.0-beta.2: the **`setup-ticket-ready` lite setup track** (beta.1) and the **ACF Local JSON serialization fix to the real ACF 6/ACFE format** (beta.2).

## setup-ticket-ready: ticket readiness in minutes (from 1.4.0-beta.1)

Support colleagues can bring an unprepared project to a ticket-ready state in minutes instead of running the full 13-gate setup wizard first. Source: Confluence Skill-Einreichung `[Skill] setup-ticket-ready` (page 1971191811, grill-me decision log 2026-09-03); proof case Fandler WP-42325, where a two-point fix took less time than the setup before it and ended in a hard blocker because the project deploys `master` over WP Pusher.

- **`setup-ticket-ready` Skill** (new): resumable lite wizard in the same `PROJECT-CONTEXT.md` schema as `setup-local-project`. Six mandatory gates: repo clone with hostname folder; `.env` plus REST test with `manage_options`; minimal `PROJECT-CONTEXT.md` (URLs, theme path, deploy path, Jira site URL and project key, working branch); working branch resolved including the legacy state; Atlassian MCP with Jira as the blocking surface; Playwright MCP. On-first-need gates recorded as `pending: on first need` (status bridge, Figma MCP, Confluence anchor); consciously excluded full-setup gates recorded as `pending: Voll-Setup` so `setup-local-project` resumes exactly there.
- **`jira-ticket-workflow`**: step 0 gate check routes open mandatory gates to `setup-ticket-ready` (the colleague only pastes the ticket link); the marker-based served check covers projects without a bridge or with `deployed_commit: null`; the Jira solution comment follows the support standard (no addressee, simple, informative, calm; hash and paths in the work record, not the ticket); in the legacy branch state the agent prepares the commit and hands over.
- **`deploy-and-branches` Rule**: `Working branch: master — user commits` is a recognized recorded state, not a per-ticket contradiction stop. The agent never commits there — it prepares and the colleague commits and pushes; all other protections stay in force.
- **`setup-local-project`** points support-only work to the lite track and resumes lite-prepared projects at their `pending: Voll-Setup` markers; **`agent-routing`** lists the new Skill under the deliberately-not-routed wizards.

## ACF Local JSON serialization matches ACF 6/ACFE (from 1.4.0-beta.2)

The serialization format that `setup-acf-local-json` and the `acf-local-json` Rule prescribed (`\uXXXX` unicode escapes, top-level `acfe_autosync`) came from the 0.8.0 source project and was taught as universal. At Quality Austria (ACF 6.x + ACFE, 62 groups) every seed deviated from the first admin save and had to be re-serialized. Source: Confluence bug entry page 1973813251 (Tobias Uhl); maintainer analysis `plugin-feedback/acf-json-serialization.md`. The setup flow itself was correct — only the prescribed file format was wrong.

- **Canonical encode style is now ACF 6** (`JSON_PRETTY_PRINT | JSON_UNESCAPED_UNICODE`): raw UTF-8 for non-ASCII (no `\uXXXX`), `\/` stays escaped, 4-space indentation, LF plus trailing newline. A differing write format recorded in `PROJECT-CONTEXT.md` wins.
- **ACFE autosync opt-in default is the nested shape** `"acfe": { "autosync": ["json"] }`; the legacy top-level `"acfe_autosync"` is documented for older ACFE versions. The shape is never guessed — read from `PROJECT-CONTEXT.md` or from a file the installation wrote itself. Semantics unchanged: `"json"` must appear in the autosync value.
- **`setup-acf-local-json` Step 5 grows from a filename check to a canonical write-format check**: after the first admin save, read filename, unicode escaping, autosync shape, and newlines; record them in `PROJECT-CONTEXT.md`; align the seeds once; then accept.
- **One-pass serialization is an explicit rule**: exactly one `json_decode` followed by one `json_encode`; double-encoding produces triple-escaped slashes (`6\\\/12`) that corrupt stored values.
- **`.gitattributes` recommendation** for the project repo: `acf-json/*.json text eol=lf`.
- Follow-through in the copy surfaces: the JSON group shapes in both WST references, the short autosync formulations in both workflow SKILLs and `migrate-ssh-to-local`, the manifest descriptions, and three new ACF rows (filename convention, encode style, autosync shape) in `project-template/PROJECT-CONTEXT.md`.
