# SmartFlow 1.4.0-beta.2

The ACF Local JSON serialization guidance now matches what a real ACF 6.x/ACFE installation actually writes. The previous format (`\uXXXX` unicode escapes, top-level `acfe_autosync`) came from the 0.8.0 source project and was taught as universal; at Quality Austria (ACF 6.x + ACFE, 62 groups) every seed deviated from the first admin save and had to be re-serialized.

Source: Confluence bug entry `[Bug] setup-acf-local-json: Serialisierung (uXXXX, top-level acfe_autosync) weicht vom realen ACFE-Install ab` (page 1973813251, Tobias Uhl, Quality Austria / qualityaustria.com.weseo.dev, plugin 1.3.0). Maintainer analysis: `plugin-feedback/acf-json-serialization.md`. The setup flow itself (inventory, split, opt-in, empirical check, byte-level acceptance) was correct — only the prescribed file format was wrong.

## Changed

- **Canonical encode style is now ACF 6** (`JSON_PRETTY_PRINT | JSON_UNESCAPED_UNICODE`) in the `acf-local-json` Rule, the `setup-acf-local-json` Skill, and both WST reference JSON shapes: raw UTF-8 for non-ASCII (umlauts stay literal, no `\uXXXX`), `\/` stays escaped, 4-space indentation, LF line endings with a trailing newline. If `PROJECT-CONTEXT.md` records a different empirically determined write format, that format wins.
- **ACFE autosync opt-in default is the nested shape** `"acfe": { "autosync": ["json"] }` (what current ACFE writes); the legacy top-level `"acfe_autosync": ["json"]` is documented as what older ACFE versions write. The shape is never guessed — it is read from `PROJECT-CONTEXT.md` or from a file the installation wrote itself. Semantics unchanged: `"json"` must appear in the autosync value, otherwise saving silently writes nothing.
- **`setup-acf-local-json` Step 5 grows from a filename check to a canonical write-format check**: after the first admin save, read filename pattern, unicode escaping, autosync shape, and newline behavior from the server file; record all of it in `PROJECT-CONTEXT.md`; align the seeds once; only then accept. Acceptance and failure handling name the byte-mismatch symptom and route it back to this step.
- **One-pass serialization is now an explicit rule** (Skill Step 3, Rule pitfalls): exactly one `json_decode` followed by one `json_encode`. A two-stage pipeline double-encodes and produces triple-escaped slashes (`6\\\/12`) that corrupt stored values — observed as a separate execution error in the source run.
- **`.gitattributes` recommendation** (project repo, not plugin content): `acf-json/*.json text eol=lf`, recommended in Skill Step 2 and re-checked at acceptance, so Windows checkouts do not break the byte-level FTP comparison.
- Follow-through in the copy surfaces agents actually copy from: the JSON group shapes in `wst-section-workflow/reference.md` and `wst-new-post-type/reference.md` (nested `acfe.autosync`, ACF 6 encode note, PROJECT-CONTEXT override sentence), the short autosync formulations in both workflow `SKILL.md`s and `migrate-ssh-to-local`, and the manifest descriptions of the Rule and the Skill.
- `project-template/PROJECT-CONTEXT.md` gains three ACF rows for the empirically determined values: filename convention, encode style, autosync shape.

## Notes

- Historical release notes and the 0.8.0 feedback doc `plugin-feedback/acf-local-json-workflow.md` stay unrewritten; the latter gains one addendum sentence that encoding and autosync shape are empirical per installation since the Quality Austria finding.
- The Quality Austria acceptance does not need to be replayed: the byte-level comparison is documented in the Confluence entry (62/62 groups byte-identical after the workaround re-serialization).
