# SmartFlow 0.7.0-beta.2

Wave-1 follow-up: WordPress content edits become a Skill, and the useful orchestration practices from Tobias' `/rekursiv` command land in the existing subagent workflow. The Commands folder stays empty — Skills are the slash entry points (`/content`, `/wst-section-workflow`, …).

## Added

- `content` Skill (from the zip `/content` command, adapted to SmartFlow): edit page, post, and ACF options values over REST. Mandatory backup under `tmp/<task-slug>/` before every write, full Flexible Content array round-trip (field name from `PROJECT-CONTEXT.md`), UTF-8 JSON with real characters, cache flush through the status bridge, and work-record notes. New layouts, templates, and CSS stay out of scope; new media goes through `wp-media-import`; title/subtitle Format vs Style follows `headline-filling`. Content writes hit the database immediately and do not go through the deploy path.
- `wordpress-content-editing` Rule (from the legacy WordPress Server Ops rule, adapted): the safety bar for every content write — read first, preserve the full array, change only requested fields, normalize types, stop before live unless confirmed. The Skill is the invoked workflow; the Rule also covers content writes started from another Skill.

## Changed

- `agent-routing`: the main chat is the orchestrator (plan, spawn, integrate; no leaf-scale file reads in the parent context). Leaf prompts are self-contained. Parallel only for disjoint write scopes; same files stay sequential. A filling context window returns `STATUS: handoff` with a fixed schema; the main chat stores it under `tmp/<task-slug>/` and respawns the same agent type. Stall stop after no-progress handoffs or more than 3 resumes per leaf task. Secrets never go into prompts or handoff files. Leaves still never spawn further subagents — that `/rekursiv` allowance is deliberately not taken.
- All five package agents accept `handoff` in their return `STATUS` and point at the schema instead of spawning to continue.
- `headline-filling` routes the actual REST write to `content`.

## Notes

- `/rekursiv` itself is not ported. The generic "split any large task" command stays with Tobias; SmartFlow only absorbs the practices that fit the two-level package-agent model.
- Boundary update versus 0.7.0-beta.1: SmartFlow now absorbs `/content` as a Skill. `/rekursiv` remains Tobias' command. The Commands layer stays unused by decision.
