# WST Builder Plugin 0.2.1

Critical safety patch. Hardens WST Builder against the ACF/ACFE clone-source data-loss class after a re-order script deleted shared ACF source field definitions site-wide on a real install. Guidance-only; no workflow or handoff-format change.

## Added

- `rules/acf-wst-patterns.mdc`: new hard "ACF Clone-Source Safety" invariants. `acf_get_fields`/`acf_get_field` are an expanded, read-only view; their entries must never be written back with `acf_update_field`. Reorder only the `menu_order` column of real direct child posts via `$wpdb`; additive `acf_update_field` is allowed only on your own new field with a fresh key and a numeric `parent`.
- `rules/acf-wst-patterns-reference.md`: new "ACF Field Definition Safety (Clone Sources)" section with the safe reorder, the safe additive-field shape, the mandatory snapshot/dry-run/idempotency preflight, and a clone-integrity scan that filters local (PHP-registered) groups.
- `skills/wst-section-workflow/SKILL.md` and `skills/wst-new-post-type/SKILL.md`: an "ACF structural write gate" before any `database/acf` field-definition write.

## Why

- A single read-then-write-back re-order loop destroyed the shared `[TMPL] Inhalt/Button/Layout` source fields, emptying those clones in every Section. Content was safe (postmeta is name-based), but editing every affected page was blocked. The guidance now makes that idiom forbidden and routes every structural ACF write through snapshot, dry-run, idempotency, and a clone-integrity scan.

## Compatibility

- Guidance-only. No change to the Section or CPT handoff format, the preview harness, or any existing selector or template contract.
- Pairs with `wordpress-server-ops` 0.6.1, which adds the generic `programmatic-acf-db-writes` Rule.
