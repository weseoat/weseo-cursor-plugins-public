# WST Builder Plugin 0.1.3

Patch release that aligns Section and CPT handoff templates with the new local Playwright MCP browser QA contract introduced in `frontend-design-qa` 0.2.0 and gives CPT work the same workflow gates as Section work.

## Changed

- `handoffs/section-handoff.template.md` QA Notes section renames `Playwright target URL` to `Browser QA target URL`, and adds `Local Playwright MCP status`, `Required viewports`, `Browser access blockers`, `Screenshot policy`, and `Project-local Playwright command` fields so Frontend Design QA can record local Playwright MCP readiness and any browser blockers alongside the existing checks-to-run and QA result.
- `handoffs/section-handoff.template.md` Local Frontend Responsibilities now require confirming Playwright MCP is ready in the local Cursor workspace (or running `frontend-design-qa` `setup-playwright-mcp`) and driving a Playwright MCP browser QA loop before optional project-local Playwright regression checks.
- `handoffs/cpt-handoff.template.md` QA Notes section renames `Playwright display URL` and `Playwright single URL` to `Browser QA display URL` and `Browser QA single URL`, and adds `Local Playwright MCP status`, `Required viewports`, `Browser access blockers`, `Screenshot policy`, and `Project-local Playwright command` fields for CPT card, archive/grid, carousel/filter, and optional single-template QA.
- `handoffs/cpt-handoff.template.md` Local Frontend Responsibilities now require confirming Playwright MCP is ready locally, driving a Playwright MCP browser loop against the CPT display URL and the representative single URL when public detail pages exist, and treating the project's Playwright command as an optional persistent regression check.
- Server-phase responsibilities in both templates clarify that the handoff must be filled before local CSS or browser QA work begins, replacing the older "before local CSS/Playwright work starts" wording.
- `wst-new-post-type` now mirrors `wst-section-workflow` with `Work type` classification, `Environment`, `Server write scope`, `Frontend route`, `Preflight gate status`, live/unknown confirmation, visual-only routing, and protected existing artifacts for CPT remodels.
- `handoffs/cpt-handoff.template.md` now includes `Workflow Routing`, `Protected Existing Artifacts`, `Source status`, and `CSS status` fields so CPT handoffs can gate server writes the same way Section handoffs do.

## Notes

- Filled Section and CPT handoffs from earlier releases continue to validate. New handoffs should fill the new local Playwright MCP and browser access fields.
- WST Builder still owns the handoff templates and server-phase ownership of the cross-plugin contract. Local Playwright MCP setup itself is owned by `frontend-design-qa` `setup-playwright-mcp` and runs only in the local Cursor workspace.
- No changes to `grill-me` or the ACF/WST/WPGB invariant rules.
