# WST Builder Plugin 0.3.0-beta.1

Beta build under test. Adds project-local Section preview pages (a "preview harness") so the local frontend phase can check a single Section in isolation under a stable URL, with fixed fixture data and stable QA hooks, instead of parsing a full customer page. Distilled from a full Section remodel pilot (2026-06).

## Added

- `skills/section-preview-harness/SKILL.md` and `REFERENCE.md`: set up and operate Section preview pages that render one WST Section in isolation at `/section-preview/<section>/<variant>` from exported JSON fixtures, through the real WST render path (`acf_setup_meta` + the real Section template). User-facing wording leads with "Section preview pages (Preview)"; "harness" is the technical term.
- `skills/section-preview-harness/reference-implementation/`: generic, copy-into-the-child-theme PHP for the route/query-hardening/render (`section-preview-harness.php`), the preview page template (`_preview-template.php`), the fixture exporter (`_export-fixtures.php`), and a structural preview-QA example. Project values (page IDs, brand slugs, hosts, Figma IDs) are placeholders. The preview template assumes an Astra child theme and documents how to adapt it.

## Changed

- `skills/wst-section-workflow/SKILL.md`: for every built Section the workflow now actively offers to set up Section preview pages when the project has none, runs `section-preview-harness` on yes, and records `section-preview-pages: declined` on no (so it does not ask again). When preview pages exist it routes multi-variant work through them and records the preview URLs. Adds the migration/finalization flow to a canonical catalog page, three new hard safety stops (backend review before fixture export, replace-or-keep before migration, test-page deletion after confirmation), a raw-title/`wpautop` template invariant, and preview-URL plus blocker-re-routing bullets in the Frontend QA Brief.
- `rules/acf-wst-patterns.mdc`: short invariants for resolving the page Flexible Content field through the post-type-`page` field group, expanded clone field names, raw WYSIWYG title output (`format_value='0'`), programmatic `update_field` writes keeping the ACFE blob consistent, stale native metas at reused row indexes, and never anchoring QA checks on stripped HTML comments.
- `rules/acf-wst-patterns-reference.md`: detailed mechanics behind those invariants (FC field resolution, `update_field` and append-only migration, ACFE hybrid mode, autop output, virtual routes alongside WST, and QA fetch pitfalls).
- `handoffs/section-handoff.template.md`: adds a mandatory `Preview URLs` field in Section Identity (real URLs or `n/a (no preview pages)` / `n/a (declined)`), an offer-to-set-up server checklist item, a preview-first local checklist item, and a Preview URLs line in the Frontend QA Brief.

## Notes

- Section preview pages are optional project-local infrastructure inside the child theme. The `Preview URLs` field is always present but accepts `n/a`, so projects without preview pages are never blocked.
- Setup is confirmation-gated server work: it copies PHP into the child theme, edits `theme-functions.php` only after explicit confirmation, and flushes rewrites. It never replaces server WST work, local `frontend-section-qa`, or final full-page verification.
- Pairs with `frontend-design-qa` 0.4.0-beta.1, which consumes preview URLs as first browser targets and adds the cached-page reality check and server-blocker re-routing.
- Repo-level `section-handoffs/section-handoff.template.md`, `schemas/section-handoff.schema.json`, and `scripts/validate-section-handoffs.py` are updated for the `Preview URLs` field; the template drift check accepts the beta template.
