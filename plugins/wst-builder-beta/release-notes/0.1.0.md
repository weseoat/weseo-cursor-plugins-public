# WST Builder Plugin 0.1.0

Initial tracer release for reusable WST builder guidance.

## Added

- `acf-wst-patterns` Rule for reusable ACF Flexible Content, clone child field, WST shortcode, and Section template invariants.
- Supporting ACF/WST pattern reference material for field structure, clone group expectations, shortcode tables, template shape, and post-meta notes.
- `wst-new-fc-section` Skill for creating a WST Flexible Content Section foundation.
- Cleaned FC Section reference material bundled with placeholders for clone groups, Flexible Content fields, layout keys, field post IDs, template paths, CSS paths, and handoff values.
- `wst-new-post-type` Skill for creating a WST Custom Post Type foundation.
- Guidance for WST Section template creation and `flexible-content.php` registration.
- Guidance for creating an ACF section field group with standard content, button, and layout clones.
- Guidance for adding a Flexible Content layout and clone child field with matching `parent_layout`.
- Guidance for CPT setup, optional taxonomy setup, ACF CPT fields, WP Grid Builder grid/card foundation, card templates, and optional single templates.
- CPT reference guidance for safe defaults, explicit no-detail/no-taxonomy/no-WPGB decisions, dedicated CPT handoff vocabulary, unresolved placeholders, and Frontend Design QA routing.
- Required `grill-me` preflight and prefilled Section handoff draft before server-side Section setup.
- Required `grill-me` preflight and dedicated CPT handoff draft before server-side CPT setup.
- Explicit routing from completed Section handoffs to `frontend-section-qa` and completed CPT handoffs to `cpt-frontend-qa`.
- Generic example showing the workflow with project-local values supplied by `PROJECT-CONTEXT.md`.
- Documentation that plugin packages are the canonical reusable workflow source and legacy SmartFlow guide material is source/archive material only.
- Package documentation for the cross-plugin contract: WST Builder owns preflight and server-side handoff creation, while Frontend Design QA owns final tracked CSS/SCSS implementation, responsive QA, Playwright-oriented acceptance, and QA writeback.

## Notes

- Project-specific ACF keys, field post IDs, CPT names, URL slugs, WPGB IDs, paths, URLs, cache commands, and theme values are read from project context.
- Concrete Section and CPT handoff storage locations are project-configured values, not reusable plugin defaults.
- Final CSS refinement, Chrome Local Overrides spikes, responsive QA, and Playwright checks remain part of the local frontend phase.
- Handoffs are the shared contract between WST Builder server-side ownership and Frontend Design QA local implementation ownership.
- Stop before implementation when preflight cannot resolve blocking project facts such as target URLs, stable selectors, storage locations, ACF/WST references, WP Grid Builder IDs, or branch/PR carrier.
