# WordPress Server Ops Plugin 0.5.0

Adds a new `project-rules-cleanup` Skill for projects that were originally set up from the older `weseo-smartflow-frontend-guide` and now use the co-installed `wordpress-server-ops`, `wst-builder`, and `frontend-design-qa` plugins. The Skill is independent of `setup-orientation`; setup recommends it as a follow-up when it detects non-skeleton `.cursor/rules/*.mdc` files.

## Added

- New Skill `project-rules-cleanup` at `plugins/wordpress-server-ops/skills/project-rules-cleanup/SKILL.md`. Guided German wizard that audits `.cursor/rules`, `.cursor/skills`, and `PROJECT-CONTEXT.md`, classifies each Rule, migrates clearly non-secret project values into `PROJECT-CONTEXT.md`, warns when more than two Rules use `alwaysApply: true`, and deletes generic legacy Rules only after explicit confirmation. Real tokens, application passwords, SSH keys, dumps, and token-bearing URLs stay out of chat, `PROJECT-CONTEXT.md`, Git, commits, tracked files, diagnostics, screenshots, and public webroot artifacts during cleanup just as they do during setup.

## Changed

- `setup-orientation/SKILL.md` Step 7 now also detects non-skeleton `.cursor/rules/*.mdc` files and recommends `project-rules-cleanup` as a separate follow-up Skill instead of mixing rule cleanup into the first-run setup wizard. The setup wizard still owns the `.cursor` skeleton and never edits or deletes Rule files itself.
- `setup-orientation/reference.md` adds a Cursor Rules Cleanup Walkthrough section that describes when to recommend `project-rules-cleanup`, how the two Skills relate, and the wizard's classification model and stop conditions.
- `wordpress-server-ops` README documents the new Skill alongside `setup-orientation` and `wp-media-import`, including the audit-first contract, classification model, `alwaysApply` hygiene threshold, conflict policy, and read-only handling of `.cursor/skills`.
- Plugin manifest, plugin descriptor, and release-notes pointer reflect the new Skill and the bumped version.

## Compatibility

- Existing setup gates and safety boundaries are unchanged. The new Skill never runs automatically and never edits or deletes files without explicit confirmation. `.cursor/skills` is audited read-only and is never deleted by `project-rules-cleanup`. Project Context, Section/CPT handoff storage contracts, WP-CLI/cache guidance, content editing, media import, and frontend onboarding behavior are unchanged.
- Real access values still must not be written to chat, `PROJECT-CONTEXT.md`, Git, commits, tracked files, diagnostics, screenshots, or public webroot artifacts. The new Skill follows the same redaction rules as `setup-orientation`.

## Notes

- `project-rules-cleanup` is intentionally separate from `setup-orientation`. Setup remains responsible for first-run setup; cleanup remains responsible for Rule migration and hygiene.
- The Skill is bundled inside the plugin package and does not depend on `weseo-smartflow-frontend-guide`, `.agents`, `.scratch`, `.cursor/plugins/cache`, or any other development-only path. Detection hints reference legacy SmartFlow Rule shapes by name and content patterns, not by reading the legacy repository directly.
