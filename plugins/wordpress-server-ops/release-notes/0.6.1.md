# WordPress Server Ops Plugin 0.6.1

Critical safety patch. Adds a generic Rule that prevents programmatic ACF field-definition writes and direct database writes from deleting shared ACF clone source fields, after a re-order script caused site-wide loss of source field definitions on a real install.

## Added

- New Rule `programmatic-acf-db-writes` at `rules/programmatic-acf-db-writes.mdc`. Treats ACF field-list reads (`acf_get_fields`/`acf_get_field`) as read-only, forbids the read-then-write-back idiom, allows additive `acf_update_field` only on a new field with a fresh key and a numeric `parent`, restricts reorders to the `menu_order` column of real child posts via `$wpdb`, and requires snapshot, dry-run, idempotency, rollback, and post-write verification for every structural write. WST/ACFE clone specifics are routed to the `wst-builder` `acf-wst-patterns` Rule.

## Changed

- Manifest, plugin descriptor, README "Included Content", and release-notes pointer reflect the new Rule and the bumped version.

## Compatibility

- Additive Rule; existing setup gates, safety boundaries, and Skills are unchanged.
- The Rule is `alwaysApply: false` and triggers when a task involves programmatic ACF or database writes. It complements `wordpress-content-editing`, which covers page and post values.
