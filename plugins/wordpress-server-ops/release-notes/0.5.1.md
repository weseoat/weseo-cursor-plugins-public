# WordPress Server Ops Plugin 0.5.1

Adds a new `project-rule-authoring` Skill that wraps the generic Cursor built-in `create-rule` flow with WESEO-specific decisions for projects that use the co-installed `wordpress-server-ops`, `wst-builder`, and `frontend-design-qa` plugins. The Skill is independent of `setup-orientation` and `project-rules-cleanup`; it runs whenever a colleague wants to add a new project-local Cursor Rule.

## Added

- New Skill `project-rule-authoring` at `plugins/wordpress-server-ops/skills/project-rule-authoring/SKILL.md`. Guided German wizard that reads `.cursor/rules` and `PROJECT-CONTEXT.md` first, runs a short grill one question at a time, classifies the request into a carrier (`project-rule`, `project-context-value`, `project-skill`, `plugin-guidance-existing`, `plugin-guidance-gap`, or `suspicious-or-unsafe`), applies an `alwaysApply` hygiene threshold, validates the planned `.mdc` against a frontmatter and content checklist, and only writes the file after explicit confirmation. Real tokens, application passwords, SSH keys, dumps, and token-bearing URLs stay out of chat, `PROJECT-CONTEXT.md`, Git, commits, tracked files, diagnostics, screenshots, and public webroot artifacts during authoring just as they do during setup and cleanup.

## Changed

- `wordpress-server-ops` README documents the new Skill alongside `setup-orientation`, `wp-media-import`, and `project-rules-cleanup`, including the grill-first authoring contract, the carrier model, the `alwaysApply` hygiene threshold, and the `.mdc` validation checklist.
- Plugin manifest, plugin descriptor, and release-notes pointer reflect the new Skill and the bumped version.

## Compatibility

- Existing setup gates and safety boundaries are unchanged. The new Skill never runs automatically and never writes a Rule without explicit confirmation. `setup-orientation` still owns the `.cursor` skeleton and the Project Context contract. `project-rules-cleanup` still owns legacy Rule migration, classification, and `alwaysApply` hygiene for existing Rules. `project-rule-authoring` only covers the authoring path for new Rules.
- Real access values still must not be written to chat, `PROJECT-CONTEXT.md`, Git, commits, tracked files, diagnostics, screenshots, or public webroot artifacts. The new Skill follows the same redaction rules as `setup-orientation` and `project-rules-cleanup`.

## Notes

- `project-rule-authoring` does not replace the generic Cursor built-in `create-rule` Skill. It wraps the WESEO-specific authoring decisions around it so that the built-in format guidance stays available while the WESEO-specific reuse check, carrier decision, and `alwaysApply` hygiene are enforced before any new `.mdc` is written.
- The Skill is bundled inside the plugin package and does not depend on `weseo-smartflow-frontend-guide`, `.agents`, `.scratch`, `.cursor/plugins/cache`, or any other development-only path.
