# WST Builder Plugin 0.1.2

Patch release that hardens the Section workflow contract and removes the new-only assumption from the Section Skill.

## Changed

- Renamed the `wst-new-fc-section` Skill to `wst-section-workflow` so the Skill can route any Section request, not only new sections. Old references to `wst-new-fc-section` should be updated to `wst-section-workflow`.
- Section workflow now requires an explicit `Work type` classification (`new-section-foundation`, `existing-section-remodel`, `visual-only`, `unclear`) before any server-side write.
- The bundled `grill-me` preflight is now a strict write-gate: no PHP, ACF, Flexible Content, CSS/SCSS, style loader, WP-CLI, cache, or content writes occur until a concrete Section handoff draft exists in the project-configured storage location.
- WST Builder no longer creates or edits final Section CSS or SCSS over Remote-SSH. CSS paths, classes, hooks, and expected behavior are documented in the Section handoff, and new CSS files or style loader entries are produced by Frontend Design QA `frontend-section-qa` in tracked local source files.
- `existing-section-remodel` is now an explicit protected mode. Layout name, layout key, `parent_layout`, ACF field keys, template path, and public selectors are preserved by default; new artifacts require explicit handoff approval.
- Added a live or unknown environment write-confirmation gate. Concrete write scope, files, ACF objects, content changes, rollback path, and cache action must be confirmed before any change. Cache flushes on `live` or `unknown` require their own explicit confirmation.

## Added

- `Workflow Routing` and `Protected Existing Artifacts` sections in the bundled `handoffs/section-handoff.template.md` for `Work type`, `Environment`, `Server write scope`, `Frontend route`, `Preflight gate status`, `Live or unknown write confirmation`, `CSS status`, and existing-artifact preservation values.
- Generic examples for new Section foundation, existing Section remodel, visual-only routing, and live or unknown environment writes inside `skills/wst-section-workflow/SKILL.md`.
- `skills/wst-section-workflow/reference.md` reusable lookup material covering shared clone groups, Section field group shape, Flexible Content layout wiring, registration, CSS hook documentation, live or unknown environment confirmation prompts, and handoff draft expectations, all work-type-aware.

## Notes

- Filled Section handoffs from earlier releases continue to validate, but new handoffs should fill the `Workflow Routing` and, where applicable, `Protected Existing Artifacts` sections.
- Visual-only Section changes route directly to Frontend Design QA `frontend-section-qa`; this Skill stops server-side work in that case.
- The `wst-new-fc-section` directory has been removed. Cross-plugin references in `wordpress-server-ops` and `frontend-design-qa` package docs were updated to name `wst-section-workflow` instead.
