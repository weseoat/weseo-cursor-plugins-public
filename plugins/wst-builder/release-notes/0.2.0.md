# WST Builder Plugin 0.2.0

Replaces the free-form `Expected Visual Behavior` prose in the Section handoff with a measurable `Visual QA Targets` matrix and splits the design reference into desktop and mobile frames, so visual intent becomes individually checkable QA targets for the local frontend phase. Promoted from `0.2.0-beta.1` after validation against a real Section.

## Changed

- `handoffs/section-handoff.template.md`: the `Expected Visual Behavior` section is replaced by `Visual QA Targets`. One row = one verifiable expectation (`Variant | Viewport | Expectation | Result`), with mandatory base variants (default, long headline/copy, optional field empty, many repeats, mobile stack, interaction states) that must be answered or marked `n/a: <reason>`.
- `handoffs/section-handoff.template.md`: viewport roles (desktop/tablet/mobile) map to project pixel widths from `PROJECT-CONTEXT.md`; missing widths stay `<unresolved: ...>` instead of invented values.
- `handoffs/section-handoff.template.md`: three phrasing rules above the matrix keep expectations yes/no-checkable, name theme tokens where they define a value, and use the stable selectors from CSS Hooks.
- `handoffs/section-handoff.template.md`: `Source design/reference` is split into `Design desktop` and `Design mobile` in Section Identity and Discovery Sources. Mobile expectations must be sourced from the mobile frame; a missing mobile design is recorded explicitly as `no-mobile-design: derived-from-desktop`.
- `skills/wst-section-workflow/SKILL.md`: the server phase fills the `Visual QA Targets` matrix (viewport mapping, all base variants answered or `n/a`, mobile rows sourced from `Design mobile`) before writing the Frontend QA Brief and routing to `frontend-section-qa`.

## Notes

- Section handoffs only. The CPT handoff template is unchanged and follows after the matrix is validated more broadly.
- Filled handoffs from older releases keep working; local QA treats a legacy `Expected Visual Behavior` table as the contract and records the missing matrix as a known risk.
- Pairs with `frontend-design-qa` 0.3.0, which verifies the matrix row by row and writes per-row results back.
