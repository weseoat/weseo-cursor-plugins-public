# WordPress Server Ops Plugin 0.4.4

Polishes the frontend onboarding handoff and the `setup-orientation` boundary so the new local-only Playwright MCP ownership in `frontend-design-qa` 0.2.0 is named explicitly. No new Remote-SSH gates are added.

## Changed

- `setup-orientation/frontend-onboarding.md` now states that `Playwright MCP` is set up only in the local Cursor workspace through `frontend-design-qa` `setup-playwright-mcp` and never inside the `Remote-SSH` server workspace. The "Drei Plugins" table and the local frontend workspace section name Browser-QA über `Playwright MCP` (navigation, snapshot, screenshot, desktop/tablet/mobile viewports, selector and computed-style checks) as the primary local browser-driving mechanism, with project-local Playwright tests as optional persistent regression checks.
- `setup-orientation/SKILL.md` "Not In Scope" now explicitly excludes Playwright MCP setup and project-local Playwright regression tests from the Remote-SSH wizard and routes Playwright MCP to `frontend-design-qa` `setup-playwright-mcp` in the local Cursor workspace.
- `setup-orientation/reference.md` Cursor Guidance Walkthrough notes that `setup-playwright-mcp` is local-only and is not verified inside the Remote-SSH workspace.

## Notes

- WordPress MCP and Figma MCP remain the only required MCP gates in the Remote-SSH `setup-orientation` wizard. Playwright MCP is intentionally not added as a Remote-SSH setup gate because it must launch a browser process on the developer's local machine.
- `.cursor/mcp.json` policy is unchanged: untracked file in the opened Cursor workspace, real values never in chat, tracked files, diagnostics, screenshots, or commits.
- No changes to Rules, file boundaries, webroot safety, WP-CLI/cache guidance, content editing, media import, or `PROJECT-CONTEXT.md` contract.
