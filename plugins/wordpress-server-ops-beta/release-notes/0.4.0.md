# WordPress Server Ops Plugin 0.4.0

Turns `setup-orientation` into a guided wizard that fully covers the old SmartFlow setup guide while modernizing it for the current three-plugin workflow and `PROJECT-CONTEXT.md` model.

## Changed

- Refactors `setup-orientation/SKILL.md` into a concise wizard contract with German guidance, robust starting state, and short confirmations before sensitive actions.
- Treats `PROJECT-CONTEXT.md` as the required non-secret context contract for later WordPress, WST, and Frontend Skills, including all SmartFlow placeholder categories (CPTs, Page IDs, FC Field Keys, Clone Group Keys, ACF IDs, button variants, container widths, clamp values).
- Replaces the legacy "SmartFlow Content Repository herunterladen" step. The wizard relies on the personal Cursor plugins (`wordpress-server-ops`, `wst-builder`, `frontend-design-qa`) and creates a tracked `.cursor` skeleton (`.cursor/rules/.gitkeep`, `.cursor/skills/.gitkeep`) for project-specific Rules and Skills, while keeping `.cursor/mcp.json` ignored.
- Verifies the WST stack (Astra Child Theme, WST plugin, ACF PRO, ACF Extended, WP Grid Builder, CPT UI) and records status in `PROJECT-CONTEXT.md`.
- Uses `git fetch origin` for Git access verification instead of a blind `git pull origin master`.
- Walks the user through the integrated Cursor terminal for hidden Bitbucket token entry, with detailed step-by-step instructions for team members who are not familiar with the terminal.
- Treats WordPress MCP and Figma MCP as required setup gates with explicit `pending: <reason>` allowed.
- Runs the documented cache flush as part of setup once WP-CLI and the WordPress root are verified.

## Added

- `setup-orientation/frontend-onboarding.md`: optional modernized handoff resource covering the three-plugin workflow, Remote vs local work, Figma usage in both Remote/WST preparation and local QA, `PROJECT-CONTEXT.md` as the project facts source, and `LEARNINGS.md` versus plugin Rules.
- Coverage mapping in `setup-orientation/reference.md` showing how every section of the old `smartflow-setup-guide.md` is covered or modernized.

## Compatibility

- Existing projects using `wordpress-server-ops` should refresh the WESEO marketplace or plugin cache to pick up the updated setup wizard behavior.
- Projects that previously committed plugin Rules or the SmartFlow Content Repo into their WordPress root can keep their existing `.cursor/` content; the wizard will not overwrite project-specific Rules or Skills.
