# Frontend Design QA Plugin 0.1.0

Initial tracer release for reusable local frontend implementation and visual QA guidance.

## Added

- `css-guideline` Rule for CSS and SCSS conventions, rem scaling, variables, selectors, responsive strategy, and formatting.
- `css-theme-styles` Rule for reusable WST and Astra styling patterns.
- `figma-to-code` Rule for translating Figma layout, spacing, typography, media behavior, and specificity constraints into project code.
- `frontend-section-qa` Skill for consuming a filled Section handoff, implementing tracked CSS or SCSS changes, using Chrome Local Overrides as spike-only work, and documenting responsive and Playwright-oriented acceptance checks.
- `cpt-frontend-qa` Skill for consuming a WST Builder CPT foundation handoff and finishing local frontend presentation for CPT cards, archive/grid views, and optional single templates.
- README documentation for required project context, handoff consumption, missing-fact stop conditions, Chrome Local Overrides policy, QA writeback, and Playwright-oriented acceptance.

## Notes

- Project-specific theme tokens, Figma style mappings, URLs, repository details, deployment steps, WP Grid Builder IDs, and test commands are read from project context, the Section handoff, or the CPT foundation handoff.
- Server-side WST template creation, ACF wiring, WP-CLI work, media import, and Remote-SSH operations remain outside this plugin.
- The filled Section or CPT handoff is the shared source of truth between WST Builder server-side ownership and Frontend Design QA local implementation ownership.
- Final CSS or SCSS changes must live in tracked project files. Chrome Local Overrides are spike-only and must be discarded or copied into source before QA is complete.
- Local frontend QA writes responsive findings, Playwright results or acceptance paths, cache notes, remaining risks, and implementation notes back to the same handoff that started the phase.
