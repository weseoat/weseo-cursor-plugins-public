# Frontend Design QA Plugin 0.2.0

Adds local Playwright MCP ownership and a browser-driven QA loop to Frontend Design QA. Browser interaction for CSS and SCSS work is now driven through Playwright MCP from the local Cursor workspace, and project-local Playwright test commands become optional persistent regression checks instead of the primary acceptance path.

## Added

- `setup-playwright-mcp` Skill for configuring the Playwright MCP server in the local Cursor workspace's untracked `.cursor/mcp.json`, verifying the browser tools against the active Section or CPT handoff target URL, and recording `playwright_mcp: ready` or `pending: <reason>` in `PROJECT-CONTEXT.md` and the active handoff. The Skill is local-workspace-only and must not run inside a Remote-SSH workspace.
- Playwright MCP preflight in `frontend-section-qa` and `cpt-frontend-qa`: confirm the local Playwright MCP server is ready or route back to `setup-playwright-mcp` before browser QA begins.
- Playwright MCP browser QA loop in `frontend-section-qa` and `cpt-frontend-qa`: navigate, snapshot, screenshot, switch viewports, locate stable selectors, inspect computed style or bounding boxes when exposed, edit tracked CSS or SCSS, rebuild generated CSS when required, and re-check across desktop, tablet, and mobile.
- README and `local-phase-boundary` Rule allowances for local Playwright MCP setup, the browser QA loop, and explicit handoff QA writeback fields for local Playwright MCP status and browser access blockers.
- Plugin-package-boundary guidance for the local-only Playwright MCP server entry in `.cursor/mcp.json`, with placeholder shapes only in reusable docs.

## Changed

- Responsibility and assumptions in `manifest.json` and `.cursor-plugin/plugin.json` now name local Playwright MCP setup, Playwright MCP-driven browser QA, and optional project-local Playwright regression acceptance instead of generic "Playwright-oriented acceptance".
- README sections for required Project Context and bundled content list now include the local Playwright MCP readiness field and the new `setup-playwright-mcp` Skill.
- `frontend-section-qa` and `cpt-frontend-qa` workflows, checklists, handoff writeback expectations, and concise examples now run the Playwright MCP browser loop first and treat the project's Playwright command as optional persistent regression acceptance.
- `local-phase-boundary` Rule explicitly forbids configuring Playwright MCP inside a Remote-SSH workspace and forbids committing `.cursor/mcp.json` or pasting browser cookies, basic-auth credentials, or session tokens into tracked files, chat, diagnostics, or screenshots.

## Notes

- Playwright MCP setup is local-only by design. WordPress MCP and Figma MCP remain owned by `wordpress-server-ops` `setup-orientation` in the Remote-SSH server workspace.
- The Playwright MCP server entry lives only in the untracked `.cursor/mcp.json` of the local Cursor workspace. Reusable plugin guidance shows the placeholder shape `<playwright-mcp-package>` and never hard-codes a package name, version, or credential.
- Filled Section and CPT handoffs from older releases continue to work. New handoffs should fill the local Playwright MCP status, verified browser QA URLs, viewports, browser access blockers, and screenshot policy fields added in the matching `wst-builder` release.
- Final CSS or SCSS changes must live in tracked project files. Chrome Local Overrides remain spike-only and must be discarded or copied into source before QA is complete.
- Local frontend QA writes responsive findings, Playwright MCP browser QA findings, optional project-local Playwright regression results or skip reasons, cache notes, remaining risks, route-back owners, and implementation notes back to the same handoff that started the phase.
