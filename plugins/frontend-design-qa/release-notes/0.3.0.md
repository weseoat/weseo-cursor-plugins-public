# Frontend Design QA Plugin 0.3.0

Teaches `frontend-section-qa` to consume the new `Visual QA Targets` matrix from the Section handoff: every matrix row is verified individually at its viewport and answered with a per-row result instead of a single prose QA verdict. Promoted from `0.3.0-beta.1` after validation against a real Section.

## Changed

- `skills/frontend-section-qa/SKILL.md`: inputs and handoff-mode confirmation now expect a filled `Visual QA Targets` matrix (all base variants answered or marked `n/a`) and split design references (`Design desktop` / `Design mobile`).
- `skills/frontend-section-qa/SKILL.md`: the browser QA loop verifies each matrix row at its viewport and writes the per-row `Result` (`pass` / `fail: note`) back into the matrix. The aggregate QA result field keeps only the overall status (for example `implementation pass, deployed verification pending`).
- `skills/frontend-section-qa/SKILL.md`: a `no-mobile-design: derived-from-desktop` note in the handoff counts as documented interpretation latitude for mobile, not as a missing value.
- `skills/frontend-section-qa/SKILL.md`: legacy handoffs that still carry the old `Expected Visual Behavior` prose table remain usable; the missing matrix is recorded as a known risk instead of blocking the work.

## Notes

- Section QA only. `cpt-frontend-qa` is unchanged and follows after the matrix is validated more broadly.
- Pairs with `wst-builder` 0.2.0, which introduces the matrix in the Section handoff template and fills it during the server phase.
