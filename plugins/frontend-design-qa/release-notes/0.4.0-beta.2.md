# Frontend Design QA Plugin 0.4.0-beta.2

Beta build under test. Changes the handoff cleanup timing: the active handoff or mini-handoff is now kept until the page goes live (Go-Live) instead of being deleted on a `final-source-served-pass`, so the Section/CPT context is preserved through the rest of the project.

## Changed

- `skills/frontend-section-qa/SKILL.md`: the completion step keeps the active handoff or mini-handoff in place after QA passes and removes it with `git rm` only after Go-Live (workflow checklist, "Commit And Close The Local Phase", and the concise example).
- `skills/cpt-frontend-qa/SKILL.md`: same handoff-retention change for CPT frontend work (workflow checklist, "Commit And Close The Local Phase", and the concise example).

## Notes

- Beta-only change; the stable `frontend-design-qa` plugin still deletes the handoff on completion.
- Removal at Go-Live stays a manual `git rm` plus commit and push; the Skills no longer trigger deletion on a QA pass.
- Builds on 0.4.0-beta.1 (Section preview pages as first browser targets); that behavior is unchanged.
- Pairs with `wst-builder` 0.3.0-beta.2 and `wordpress-server-ops` 0.6.1-beta.1, which carry the same handoff-retention wording in the handoff templates, the WST Section workflow, and the frontend onboarding doc.
